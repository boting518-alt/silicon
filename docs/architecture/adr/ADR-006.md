# ADR-006：OIDC、服务端身份与事务租户边界

状态：TASK-002 实施决策，交付后待独立复核。日期：2026-09-09。

## 身份与会话

沿用 Keycloak，固定 26.7.3；Java 21.0.6 已实际运行。采用 confidential client 授权码、PKCE S256、随机 state/browser 绑定与 nonce，服务端兑换并用固定 issuer/JWKS/RS256 校验签名、aud、azp、sub、iat、exp 和 nonce。只接受所配置 Keycloak 的精确 discovery endpoints，不跟随任意 IdP URL。官方依据：[Keycloak 下载](https://www.keycloak.org/downloads)、[TLS](https://www.keycloak.org/server/enabletls)、[PyJWT 验证参数](https://pyjwt.readthedocs.io/en/stable/api.html)。

数据库只保存随机会话 token 的 SHA-256、用户、选择的租户、CSRF hash 和绝对失效时间；寿命不超过 ID token exp 或 30 分钟，无自动 refresh。ID/access/refresh token 不保存。登录尝试 5 分钟、一次性消费；回调需原浏览器的 Secure/HttpOnly Cookie。登录后旋转本地会话；会话 Cookie 为 __Host-、Secure、HttpOnly、SameSite=Lax、Path=/。CSRF 使用另一 Secure Cookie，JS 只能读取 CSRF token；写请求同时验证 token hash 和固定 Origin。

退出先原子删除本地会话并审计，再由浏览器跟随 Keycloak RP logout URL、确认退出 IdP。即便 IdP 暂不可用，本地退出已完成。禁用用户立即不能使用会话；membership 每个租户事务重查。没有 IdP 管理端撤销的 back-channel 推送；其会话最多存活至现有 ID token exp，若以后要求即时远端撤销须增加并验证 back-channel logout。当前未宣称生产上线就绪。

开发 Web 与 IdP 都启用 HTTPS。自签名证书仅由显式脚本生成，API 指定 CA 验证；不关闭服务器 TLS 校验、不安装系统信任、不放宽 Secure Cookie。第一次 HTTP IdP 测试因安全 Cookie 不被 httpx 发送而失败，改为 HTTPS 后继续验证，未修改 IdP Cookie 保护。

## 数据与权限边界

identity_users（issuer/sub 唯一）、tenants、memberships、roles、permissions、role_permissions、sessions、login_attempts 是全局身份/授权控制面；一个用户可在多个企业以不同角色加入。普通 API 不提供任意身份表 CRUD。新 OIDC 用户不自动获得 membership；虚构开发成员通过显式迁移角色脚本配置，不是认证替身。

Access 统一检查操作权限、own/all 数据范围和受保护字段投影。request_tenant 只从已认证服务端 session 取得 actor/tenant；客户端请求体/查询参数不能覆盖上下文。未登录 401、缺 membership/权限/CSRF 为 403；对象不可见统一 404。字段投影发生在返回前，附件元数据与下载都经过同样的操作、数据范围和 RLS。

tenant_transaction/request_tenant 在同一事务锁定有效 membership 与用户、检查权限，使用 set_config(..., true) 设置 actor 和 tenant。commit/rollback 后上下文失效。lock_membership 是窄 SECURITY DEFINER 只读锁函数，固定 search_path 和表限定名，撤销 PUBLIC EXECUTE；原因是 PG 的 FOR SHARE 也要求 UPDATE 权限，不能为锁定而给运行角色修改 membership 的能力。

租户表采用 tenant_visible(tenant_id) 的 ENABLE + FORCE RLS；策略检查上下文与有效 membership，未设置上下文时读取零行、写入拒绝。运行角色 silicon_app 非 owner/非 superuser/非 BYPASSRLS。租户关系使用 (tenant_id,id) 主/外键，允许不同租户复用编号。当前没有业务表；成本与附件验证使用仅测试建表的夹具，不把它们作为上线功能。audit_events 为真实租户作用域记录（登录等全局事件允许 tenant=null），强制 RLS 限制读取，app 仅有 SELECT/INSERT，无 UPDATE/DELETE。

RLS 的信任边界是服务端应用角色：持有数据库凭据的受信后端可读取全局授权控制面和设置 GUC；它不是任意 SQL/被入侵后端的隔离沙箱。前端、Worker payload 或模型不得取得这些凭据。测试明确区分 owner 的建表/夹具维护和 app 的实际隔离断言。

## Worker、审计与生产保护

原 jobs 是全局调度控制面，保留 TASK-001 的有界 SKIP LOCKED 清理、租约 token、重试与防重。smoke 不带租户；新增有界 identity.check 仅执行授权检查和审计。入队须有效 membership + job.run，持久 envelope 保存 actor/tenant/request_id、复合 membership 外键；幂等域含租户、操作者、kind 和 key。没有任意 payload，更不能从 payload.tenant_id 推断授权。

执行时再次检查授权（含入队后撤销），审计和最终状态在当前租约锁内同事务写入；无上下文或无授权立即 failed，并记 denial。已有未知 smoke kind 仍按原重试策略处理。没有长任务、业务副作用或 outbox 投递器。

审计只允许 actor、tenant、action、object、outcome、request_id、时间字段，不接受敏感正文/任意 metadata。允许记录和受控状态修改同事务；拒绝在回滚后独立事务保存。HTTP 错误统一稳定 code/message/request_id，回调不输出令牌；开发启动关闭 API URL 访问日志。

保留 SILICON_ENV=production 启动拒绝。身份纵切完成不等于备份恢复、密钥轮换、远端会话撤销、入口防护、生产 IdP 运维、部署和业务权限均已验收；TASK-002 没有授权这些生产准备工作。TASK-003 不自动开始。
