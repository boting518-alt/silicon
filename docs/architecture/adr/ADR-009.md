# ADR-009：目录、技术组成与价格版本

状态：TASK-004 实现决策，等待独立审查。

## 数据边界

SKU 用稳定 id 和企业内唯一编号识别。制造商、销售品牌分别建表，品牌具有 own/third_party 属性；同名品牌不能隐式改变属性。SKU 创建/修改可按名字引用或建立这两个主数据身份，不把供应商存入其字段。首期无供应商/采购管理和内部成本字段。

规格单独关系表包含 socket、memory_generation、capacity_gb、power_w、slot_width、interface、speed_gbps、cpu_sockets，覆盖九类硬件的有限结构化表达。缺资料允许空值，不能由空值推断兼容。不是参数全集或任意 JSON 规则。发布快照使用 JSON 只是冻结这些有类型的公共模型，在线源数据仍是关系表和有类型的列。

目录为企业共享数据，不沿用 CRM 的“本人客户”过滤；catalog.read 授予 admin/member/viewer，catalog.write 仅 admin。首期普通成员不能改目录与价格，后续如需销售维护角色须明确授权。所有 catalog 表 FORCE RLS、tenant_visible、复合租户外键；运行角色不是 owner 或 BYPASSRLS。

## 事务与锁

沿用 ADR-008 的 request_tenant(require_context=True)。所有目录请求先持会话锁、验证页面 X-Expected-Tenant/X-Session-Context、真实 membership 和权限，设置事务内租户上下文，然后取得 catalog:<tenant> 的事务 advisory 锁。普通读取为 shared，所有命令为 exclusive，直到提交/回滚。之后才读幂等记录、目录父子和图关系，不再获取其他人的身份锁。

该企业级目录锁串行化多表编辑、包件图修改、发布/修订和重叠价格检查。读共享锁可并发；写量首期较低，选择粗粒度一致性而不引入多父节点锁排序。跨企业可并行，哈希碰撞最多造成额外串行等待，不造成越权。未来优化须同时保留图无环、价格无重叠和聚合一致性，不能仅删锁。产品原 3 秒 statement_timeout 保留。

全部生产目录入口由同一事务边界覆盖；可信内部服务调用也必须先 guard，不提供绕开锁的 Worker/公开探针。直接写 SQL 不是对外授权 API；数据库另有正数/FK/唯一键和发布不可变触发器作为第二道约束。

幂等作用域为 tenant/actor/operation/key，保存请求 hash 与完整响应，事务原子提交；同 key 改内容返回 IDEMPOTENCY_CONFLICT。更新/发布/修订校验 expected_version。上下文先于幂等结果检查，旧页面不能借历史 key 获得错企业响应。前端复用 CrmRequests 的不可变 ticket/成功响应代次检查，目录组件在模式/企业改变后卸载，清除表单与异步状态。

## 包件、BOM 与规则

catalog_boms 的 kind 分 package/bom。package 表示主体主机 SKU 的包含清单，部件行只能 included；bom 可引用 SKU 或其已发布 package 版本，行含数量、必选/可选、included/separate。发布 package 版本必须匹配该行 SKU。最多 100 行、16 层、展开后 1000 行、单个展开数量不超过 1000000（保持客户端整数精确）；正整数数量，不允许主体自引用或沿嵌套版本重遇祖先 SKU，即使版本图没有指针环也拒绝业务层循环。

技术展开保留所有包含件；嵌套件始终 included，不能因为展开而生成另计价行。separate 仅表示未来需要商业定价，当前不计算报价总额。没有包含件抵扣或替换折价命令，移除/替换技术行不会改变任何价格表金额；若未来支持抵扣，必须引用明确商业价格依据。零价格条目也不自动生成包含件价格。两种虚构准系统由测试创建：含两个电源，与不含电源、需另选。

草稿编辑增加 version；发布冻结主体、规格、展开部件、规则版本/来源及检查结果。已发布父记录和子行不能 UPDATE/DELETE，SKU/规则后续变化不改旧快照；修订新建 id，同 family、revision 递增。发布是目录内容冻结，不是兼容认证或报价发布，因此允许保存/发布具有 BLOCK/UNKNOWN 的不完整包件，但必须原样展示结果，不生成“配置通过”。

规则每次创建即为不可变版本，修订需要原 revision 作为 expected_version。有限规则仅检查 CPU 插槽、内存代际、电源总容量及 N+1 对显式功率预算的关系。缺电源 BLOCK，资料不足 UNKNOWN，总量足够但 N+1 不足 WARN，匹配项 PASS 仅表示该项符合所选资料。GPU 空间、PCIe/IB 占槽、背板和内存通道没有完整资料时始终返回 COVERAGE/UNKNOWN，不给整体通过结论。来源必填；虚构例子不能称为供应商确认。

## 价格

价格表 draft/published，独立 family/revision/version。金额 NUMERIC(18,2)，Python Decimal；输入超过两位小数拒绝，不静默舍入，响应十进制字符串，零价明确 0.00。首期 CNY，不换算税额/币种、不计算尾差，不硬编码税率。tax_included 是所录金额口径，不能混用为同一种价。

适用范围是必填规范代码（如 retail），查询精确匹配，不提供默认跨范围回退。有效期使用带时区 UTC 时刻 [valid_from,valid_to)。同企业、SKU、scope、currency、tax_included 的已发布条目不允许期间重叠，发布在 exclusive guard 内检查并拒绝 PRICE_OVERLAP，包括并发发布。相邻期间允许；新修订若与旧版重叠，须先改为未来不重叠期间，不能通过缩短旧已发布期间来篡改历史。

当前价只查已发布版本，返回 KNOWN / UNKNOWN / EXPIRED / NOT_YET_VALID、十进制金额或 null、book_id、revision、source、期间及 as_of。UNKNOWN 没有金额，过期不返冒充有效的金额；零价为 KNOWN/0.00。不可变历史表/条目保留，修改 SKU 名称不改历史金额或引用 SKU id。商品/包件普通查询没有内部成本；当前价格是商业销售目录价格，不是预计采购成本。

## API 契约

统一前缀 /api/v1/catalog：skus GET/POST、skus/{id} GET/PUT；rules GET/POST、rules/{id}/revise POST；boms 和 price-books GET/POST、/{id} GET/PUT、/{id}/publish 和 /revise POST；current-price/{sku_id} GET（scope、tax_included、可选 as_of）。实体及数量/时间约束以生成 OpenAPI 为精确字段契约。

写入要求 Idempotency-Key；未登录 401、无权限 403、不可见对象 404、版本/上下文/重叠冲突 409、缺上下文 428、输入/关系错误 422。所有结果包含实际版本，不提供任意 PATCH status。列表首期最多 100 项；SKU API 支持 q/page/page_size，UI 明示当前载入上限，不冒称完整大目录搜索。

## 验证及部署边界

真实独立 PG 覆盖两个企业、角色、无上下文、FK、幂等/编辑竞争、价格发布竞争和多表读取期间写者等待。0005 从空库与 0004 升级，原客户/联系人/身份/租户任务保留。发布数据不可变触发器直接以应用角色验证。浏览器沿用可信开发 HTTPS，不改信任、不忽略证书错误。保持 production 拒绝，不启用报价工作室、采购、库存、远程或部署。

## R1/R2 修复：草稿可修复性与发布有效性

2026-09-10，依据 TASK-004-1d627b1-review 的 R1/R2，明确以下政策，优先于上文未区分生命周期的描述：

- SKU 类别允许修改；已有 package 草稿主体不再为 host 时，列表/详情仍返回完整草稿并显示 PACKAGE_REQUIRES_HOST / BLOCK。允许保存修复中间状态；发布重新检查并拒绝，修复类别或替换主体后可发布。不通过跳过该记录或吞掉异常避免页面加载失败。
- BOM 与价格表的创建、编辑、历史修订复制均为草稿操作，允许保存当前已停用的 SKU 引用；所有租户可见性、FK、数量/金额/期间、包件图防环和版本约束仍执行。发布前在同一目录写事务内重新检查主体/直接部件或价格行的当前启用状态，DISABLED_SKU 阻断发布。嵌套包件的内部技术资料仍是已发布版本快照，不递归将历史资料更新为当前 SKU；该包件直接引用的主体仍检查当前启用状态。
- BOM 草稿使用 snapshot.checks 标出失效；即使引用了旧包件快照，也不因快照里的 enabled=true 遮蔽直接引用主体的当前停用状态。价格表新增只读 checks 数组，草稿逐条标出停用 SKU；发布表返回空数组，表示没有草稿待修复项，不表示当前销售授权或供应商认证。界面明确提示先修复再发布。
- 修订仍通过原 family 创建递增 revision，幂等与 expected_version 不变；不重新启用旧 SKU、不修改旧发布 snapshot 或条目。停用后原历史价格查询语义保持既有规则，本次不新增报价/交易有效性判断。
- “发布前拒绝类别不符/停用 SKU”是目录引用有效性门槛；平台兼容示例的 BLOCK/UNKNOWN 仍可随内容冻结，例如没有电源的包件。不把两类检查混同为完整兼容认证。
