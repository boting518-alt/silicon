# ADR-007：独立客户聚合与原 UI 壳迁移

状态：TASK-003 实施决策，待独立复核。日期：2026-09-10。

## 客户与关系

客户以租户内唯一业务编号和独立 UUID 建档，不从合同数组派生。联系人、项目、装机地点是一对多子项；项目负责人和关键人均引用同一客户的联系人，一人可承担多种项目角色。内部销售/售后负责人引用本企业有效 membership，与客户侧联系人分开。

迁移 0003_crm 的复合主外键同时约束 tenant/customer/project/contact，不能把其他客户联系人挂入当前项目。将来多个合同引用同一 `(tenant_id, customer_id)`；本任务不创建合同表或模拟合同记录。角色变动关闭原任期并追加新任期，保留人员/项目名称快照和变更者；历史不随联系人、项目移除而删除，不为历史快照建立指向可删除子项的外键。

以客户为聚合边界，一次保存替换其可编辑子项，并在同一事务更新客户版本、角色历史、幂等结果与审计。子项 UUID 保持稳定，拒绝挪用其他客户已存在的 UUID。当前聚合上限为各 50 个联系人/项目/地点、每项目 50 个角色；未来大客户扩容须单独评估，不无限接收正文。

## 权限、并发与错误

沿用 ADR-006 的服务端会话、CSRF、有效 membership、事务租户上下文和 own/all 范围；所有八张 CRM 表 FORCE RLS，实际运行角色不是 owner/superuser/BYPASSRLS。新增 crm.read/write，admin/member 可写，viewer 只读；member 的 own 范围以建档者 owner_id 判断，不把内部责任人等同于数据所有者。客户字段当前没有额外敏感字段，不引入采购成本模块；原字段权限及附件边界测试继续保留。

创建/编辑必须携带 Idempotency-Key；服务端按租户、操作者、操作和 key 串行化同一请求，持久化正文 hash 与结果。相同 key/正文重放，相同 key/不同正文返回 409。编辑锁住客户行并核验 expected_version；旧版本返回 409，不覆盖已保存内容。编号数据库唯一约束处理并发不同 key 的重复创建。分页按 created_at DESC/id 稳定排序；搜索名称、编号、城市与联系人名称。

未登录 401，权限/CSRF 拒绝 403，不可见对象 404，输入/关系错误 422，并发/重复编号 409。前端提供明确错误和冲突重载入口，不展示假成功；401 清空已显示的客户与弹窗。审计只记录动作、对象、操作者、租户、结果及 request_id，不记录客户正文。原 Worker、租约、重试、生产启动拒绝不变。

## 原壳与视觉验证

从固定工作空间 Demo 的 style.css 提取适用壳/客户规则到 packages/ui/workspace.css，保持规则顺序和断点；没有引入新模板。React 独立管理 DOM，不加载原业务脚本。深绿强调、浅色背景、215px 桌面侧栏、页头、卡片和面板风格沿用原文件；原合同统计改为真实客户/联系人/项目/地区统计，未接入导航禁用并标记未启用。

原窄屏导航存在撑宽问题，本次修正为视口内换行；详情继续使用原生 dialog，并增加键盘焦点返回。新建、多联系人/项目表单、权限/失败/冲突状态在原 Demo 中没有对应完整状态，明确为新增设计。差异与两视口截图见 [视觉对照](../../design/task003-visual-comparison.md)。

只读参考按 OD-018 克隆到独立临时目录后做完整 blob/hash/fsck 核验；不修改原 Demo 或其元数据。冻结时钟/字体/动画仅存在于显式视觉测试服务与 Vite serve 插件，生产构建不注入。真实 OIDC 不用测试身份替身；浏览器使用用户明确授权的登录钥匙串 SSL 信任，测试夹具不自动修改系统信任。
