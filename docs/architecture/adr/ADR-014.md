# ADR-014 — 预留、装配与设备的单台成本闭环

status: review_ready；TASK-009。

## 事务顺序与权限

身份/会话/membership → catalog共享 → quotes共享 → inventory共享读/排他写。装配不在库存锁后申请身份、CRM、报价锁；共享文件清理既有catalog→quotes→inventory顺序兼容。全部库存相关命令保持单租户串行，跨租户可并行；聚合详情保持同一共享锁直至读取结束。后台先锁jobs租约，再授权，再按同序进入领域；HTTP只新增job，不反向锁旧job。

装配/设备权限独立；成员在企业内有仓库业务数据范围，viewer仅设备读取；不因此取得客户联系信息或采购成本。对外显式选择来源字段，不直接返回合同商业JSON；成本仅inventory.cost授权后返回。重放前重查权限、工单及来源可见性。

## 冻结映射

仅从sales_orders.content.commercial冻结config/host/calculation读取。每单quantity是设备台数，每个工单消耗一台计划额度，未领料取消释放。主体SKU一件；所选technical_lines的separate为独立实物、included仅展示不另扣。主体在technical_lines出现时忽略重复主体。每行位置为主机/类别+SKU编号；不推测名称映射，不允许替代料。若冻结数据缺少ID/数量/追踪配置或重复歧义则draft展示缺口，ready拒绝；单独成品SKU需host类别、SN追踪，由维护者明确选择。金额/现价不参与映射。

## 库存与成本

沿用inv_movements/entries/balances/layers/units。新增wip状态及每工单专属在制库位；领料为qualified→wip成对移动，同一成本层，不另记平行余额。预留按SN物理件或批次层+库位固定来源；FIFO以层created_at/id排序，减去尚有效占用，领料不能换层。未知成本可保留/预留但禁止领料，零价可用。到期UTC服务端判定，所有消费/分配前释放；持久化既有Worker延迟任务以原actor当前权限复核，撤权即拒绝，HTTP也可完成到期清理，Worker停机不影响安全。

完工扣尽该工单wip，创建一件pending成品层，成本仅实际领料合计，两位Decimal无分摊。设备只引用该inv_unit；来源sku/品牌/型号快照冻结。SN部件安装唯一，批次引用层数量，不伪造SN。完工后不能通过旧质检入口提前测试放行，TASK010未启用。

整次错误领料逆向恢复原位置，预留消费历史不擦除，需重新预留；整次错误完工逆向恢复wip、关闭安装、保留设备及全部记录。成品有任何后续未逆向移动或有效预留拒绝。原采购逆向或移库不得触及有效预留，装配移动只经装配逆向入口。未新增附件类型，现共享文件保护不变。

页面提交duration_hours，由服务端事务内当前UTC计算到期；API亦可显式提交带时区expires_at，两者必须二选一。上限8760小时为开发输入边界，不宣称企业真实预留政策。幂等摘要保存原时长意图，重放不延长到期。

重新预留先在同一排他事务内校验调用方expected_version，再清理到期行并重新读取缺口；不能让本事务自身的版本递增造成永久误报冲突。真实外部版本变化仍拒绝。

## TASK-009 R1 增量：稳定设备身份与追加完工历史

审查基准c08079e，限定错误完工更正，不引入正常返工或换件。原0010的asm_devices保留为一件实物一份设备档案，其原首次完工字段不修改；0011新增asm_completions作为逐次完工事实。安装新增completion_id，区分原已关闭关系与新有效关系。完工内容不可覆盖，仅允许一次性追加有效逆向引用，引用必须指向该完工的逆向移动。设备和工单各有“未逆向完工”部分唯一索引；原实物唯一约束继续保留。

API Complete.correction_of为明确来源声明，不是授权依据。相同身份/租户/目录/报价/库存锁序内校验来源是同工单最近的已有效逆向完工、SKU/SN对应同一实物、所有历史成品层无余额/有效预留/未逆向移动、实物无有效安装。拒绝无来源的历史SN复用、跨工单来源及跳过较新的更正记录。沿用原manufacturer/SN实物标识，追加新的成本层、移动、完工与安装；不覆盖旧设备产品快照、移动、成本层或安装。旧采购/期初入口不能重新引入已归档设备。

设备列表仍一物一档；顶层库存、金额、完成时间指向最近完工，已逆向时有效成品金额为0。completions列出全部历史；工单对账只统计未逆向完工，不能按设备历史条数累计成品或成本。新成本层仍受原“待测试、TASK010未启用”保护。

非更正Complete请求的幂等摘要排除新增null字段，以兼容0010成功命令；更正请求摘要包含correction_of，同键重放返回原结果，不再执行或继承新业务意图。旧Work响应无completions仍可重放。重放之前仍重查当前权限与预期企业。

0011在单次迁移事务持有DDL锁期间临时关闭三个来源表RLS，仅用于全租户回填；完成前重新启用，原FORCE RLS不变，新表同样FORCE RLS。事务失败全部回滚。原0010脚本不修改。回填旧设备的首个完工、已有逆向及安装关联，不重写原字段；已有更正记录时禁止降级到无法表达该历史的0010，不能丢历史以降级。
