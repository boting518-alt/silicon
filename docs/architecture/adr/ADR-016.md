# ADR-016 — 经营资金事实与分配账

status: review_ready；TASK-011。显式确认经营子台账，不建立法定总账，不调用银行或税务系统。沿用原合同/订单/客户/供应商身份，资金和发票权限不绑定库存成本。

## 来源与额度

销售来源固定signed_contracts（包含唯一sales_order），采购来源固定active inv_contracts，可附属于该合同的confirmed采购订单。按合同统一控制额度，避免合同计划和订单计划双计；每个计划有来源内唯一节点号。销售可显式导入冻结付款节点为草稿，不自动确认；未知delivery/acceptance到期以条件待释放，不推定日期。手工计划支持明确日期或待条件，质保金必须条件/释放确认；不是另一笔额外债权。

销售限额为冻结销售合同商业总额；采购为合同数量×记录单价及既有同价数量追加。税口径保留人工记录，不推定税率、可抵扣或把不含税金额自动转为含税。存在未确认税费时按合同已记录金额建立经营计划；如需额外税费或商务金额变化，finance.correct以唯一档案依据追加合同额度调整，不能覆盖源合同。普通项目增加不得突破该总限额；减少不释放出重复原合同债权的生成空间，合同计划累计原确认金额仍占额度。退货减少必须关联真实del_return及同销售合同，来源唯一，显式商业金额而非成本。修改计划确认额只能追加调整；有效额不得小于有效核销，减至零为冲销式调整。

## 事实与逆向

计划、资金、退款、发票草稿保存内容即固定，需要修正时取消草稿另建；确认后不改原金额。确认必须人工confirmed、expected_version。分配/调整/释放/逆向都是追加事实，资金与项目版本随相关操作递增。有效分配=未逆向分配；有效退款=已确认且未逆向退款。现金流按资金收付方向减去对应有效退款，核销不参与现金流。

一笔资金可原子分配到多个同往来/方向/CNY项目，重复目标拒绝；上限在同一写事务内重读。质保金或未知到期条件未释放不得核销、不列逾期；释放记录确认满足条件并给出到期日，不增加金额。资金冲销要求无有效分配/退款；退款冲销恢复原可用额；分配逆向同时恢复资金与项目余额；均不删除原事实。同一逆向来源只能一次，幂等同key返回原命令结果，但先重查全部对象的当前可见性。

资金外部流水号按tenant/account/direction唯一（确认时生效）；已冲销仍保留防重，纠正须新流水/说明，不回收旧业务流水身份。无流水号必须填写人工依据，不宣称识别所有线下重复。预收预付是资金用途标签，待分配余额保留该分类；所有资金必须关联既有客户或供应商，收应收/付应付对称。

发票为CNY人工正额登记，确认时校验同往来、来源分配合计、同一来源不重复及净开票上限；红字以原发票的来源分配为界追加负额记录（不能超出原票剩余），原正票有红字后不可整票作废，需按剩余红字更正。确认发票的标识在租户/方向内唯一，作废不复用号码。税额/不含税均空=税额未确认；齐全需净额+税额=含税额；不自动计算税率。仅档案编号，不新增附件类型或公开链接。

## 精度、授权与并发

金额最多18位、两位小数，输入拒绝浮点JSON与多余小数，Decimal/NUMERIC不隐式舍入；整数数量乘两位单价精确，求和精确到分。金额响应字符串。时间点带时区存UTC，经营日期首期明确Asia/Shanghai，过期是到期日严格早于该日且有未结余额；无日期不判逾期。实际发生时间不可晚于服务器当前时刻。

权限：finance.read、finance.plan、finance.confirm、finance.cash、finance.allocate、finance.correct、finance.invoice。只有admin默认获得写与查询；其他角色不自动获得任何资金权限。finance.read授权最小商业来源金额/往来名称，不能据ID读取其他模块字段、采购成本或附件；销售来源遵守客户owner可见性，采购来源own范围限合同manager。列表、详情、摘要、重放统一可见性。基础合同/订单页面始终先独立加载，财务摘要单独鉴权，403清除旧金额，不能导致基础页失败。

锁序：会话/membership → catalog共享 → quotes共享 → CRM客户父行按ID共享 → inventory共享 → finance租户共享读/排他写。CRM父行在inventory前，后续不调用反向加锁服务。现有合同quote排他写、采购/交付inventory排他写与资金读取保持明确顺序。财务写单租户串行是首期吞吐取舍，所有额度/原事实/分配重查同事务完成；聚合读持finance共享锁得到完整状态。所有新表FORCE RLS、复合外键，冻结触发器禁止历史覆盖；独立finance命令表，不把财务授权等同inventory权限。

空库/0012升级只追加表权限，不修改前序业务数据；存在资金台账时降级拒绝，保留历史恢复备份，不删除记录强行降级。生产模式拒绝启动保护保留。

### 查询范围细化

自有范围按销售客户负责人 / 采购合同负责人检查；供应商资金须至少存在当前操作者负责的合同。资金响应中的历史核销关系也重新检查对应计划来源可见性，不能通过历史重放取回已不可见来源。所有命令另外要求 finance.read，使写操作响应与查询权限一致。

发票创建的来源集合与红字原票 ID 参与操作作用域的 SHA-256 摘要；同一往来下不同来源可独立复用 key，同一来源意图改变金额仍冲突。退款业务流水按租户/账户/参考号唯一，保留冲销后的占用。

## R1：误减更正与新增额度分开（2026-09-11）

原负向业务调整不释放来源额度的规则保留。新增 `fin_adjustment_corrections` 只允许完整撤销某一负向调整，不接受客户端指定恢复金额、不支持部分恢复或更正的再次更正。金额由原不可变负额取反，唯一(tenant, adjustment)防止重复恢复；复合外键绑定同计划同租户。更正关联原调整、经办人、原因、依据与时间，原记录不更新。更正不计新增额度占用，但计入计划有效调整、未结和对账；原计划及所有普通正向调整仍占来源额度。

入口沿用 finance.correct、finance.read、预期上下文与来源权限；同一资金写锁内先检查计划版本和原调整，再追加与递增版本。幂等操作作用域包括计划与原调整，重放前重新验证全部关系。有效金额不得小于零或有效核销；仅恢复负额不会减少余额。后续如需再次减少，追加新的明确商业调整，不能删除更正。

退货关联的误减也可明确更正，但只恢复商业应收，不撤销实物退货、退款或核销，不重新开放该退货 ID 的防重占用。已实际退款后更正形成新的未结余额，后续收款/核销需独立登记；不能伪称退款已取消。页面必须显示此说明，用户提供更正依据；不修改源合同金额或历史实物事实。

兼容迁移 0014 只增加更正表与原调整复合唯一约束。数据库触发器验证原调整为负额，唯一约束限制一次；不可变触发器和 RLS 同前序。存在更正记录时拒绝降级；无更正可降至0013且所有既有资金事实保留。锁序不变，不建立另一套资金账。
