# ADR-017 — 售后保管、安装历史与独立服务来源

status: executing；TASK-012。用户任务书授权人工售后闭环，不能推定自动诊断、银行动作或未知保修政策。

## 身份与保管

工单只来自仍有效发出的 del_line；后端从稳定 asm_device 推导客户、订单和合同。生产未发或已销售退回设备拒绝新售后。一个设备最多一个活动工单，关闭后可明确重开或建新工单；重开追加事件。

客户整机返场仅增加 svc_custody 接收/归还事实，保存实际位置、外观与附件清单，不增加自有整机库存，不写del_returns或改变净交付/现金。上门、远程模式保管在客户处。返场更换前必须收到实物；归还须当前配置人工测试通过和解决结论，关闭须已归还。未换件也需要人工测试/客户确认才能解决。

## 状态与责任

待受理→处理中；处理中可等待备件/外部；处理或等待→待验证；当前配置测试通过+诊断/方案+客户确认→已解决；实物检查完成→关闭。已解决之后换件必须重新回处理中，并使配置版本变化、旧服务测试失效。取消仅无领料、换件、费用、活动接收或RMA；保留所有事件。保修默认待确认，人工保内/保外/特殊处理需依据，不推定年限。

## 共用库存与安装

不建平行库存账。svc_reservations仅是对既有inv_layers的占用；assembly.active统一汇总装配和售后有效占用，原库存移动/发货也沿此入口保护。预留在合格自有层按created_at/id FIFO选择；SN个别计价。领用从原qualified层移到工单专用service_issued状态，仍为自有库存，安装时才出层并计材料费用，未用退料按同层移回pending需检验。安装后禁止未用退料。未知成本不默认为零，需先有可用成本才能领用。

新增安装沿用asm_installations和原inv_unit；关闭旧行仅填写removed_at/correction_id，追加新行。不改原报价/合同/完工/发货。slot_id给历史安装子槽稳定标识（旧同position多批次行不合并）；一个有效子槽一条安装、一个SN只能一处安装。新安装沿用旧子槽、数量，校验类别一致与SKU启用；详细兼容资料不足，必须有service.replace权限人员明确人工确认和依据，输出manual/UNKNOWN，不伪称自动通过。

客户旧件不重新增加已消耗的自有层。拆下后建立同unit的customer保管层，沿原采购来源保留追溯，成本unknown但不计自有库存。客户保留无需公司库存；公司代管在隔离状态。更正换件必须最新且无RMA、归还、后续换件/领退等依赖；追加逆向移动、关闭错误新安装并新增原件安装，绝不重开或删除历史行。服务配置与原完工安装明确区分。

## RMA

RMA批次明细来自本工单已隔离旧件，关联采购供应商；不同供应商需service.correct权限与授权依据。负责人有效membership，送出从隔离移到supplier保管状态；已送出不改变所有权和财务。原件返回移动同层到pending；替换返回新SN建立新unit/customer层并保留旧新关系，不能改旧SN。逐明细返回和检验，剩余仍在外。检验后可客户归还、代管、独立报废，或有明确所有权转移/成本依据才转自有备件；不自动当零成本可售。关闭工单前代管旧件必须已有明确RMA责任或处置事实，RMA可在工单关闭后继续。

## 费用与资金

材料只在安装时按原领料层成本计一次，逆向同成本冲回。人工（人员/工时/依据/金额）、其他费用为不可变人工记录，service.cost控制人工/其他成本，inventory.cost控制材料成本，service.fee授权费用确认。

独立 svc_charges 保存customer_service或supplier_repair方向/来源/往来/金额/依据。fin_plans、fin_invoice_lines、fin_source_adjustments扩展service_source_id，继续统一source_id和原finance额度、防重、RLS、核销。服务收费先人工确认才成为资金可选来源，普通售后不自动生成债权；资金计划仍需finance.plan/confirm。supplier_repair来自RMA供应商，不虚增采购合同；服务来源金额冻结，本期不允许finance.source_adjustment对它加额，修正新来源须明确业务依据且防同依据重复。收款仅TASK011现金/核销实现。

## 锁与安全

会话/membership → catalog共享 → quotes共享 → CRM父行按ID共享 → inventory读共享/写排他 → finance读共享/写排他。售后与资金来源均遵循此序；资金读取svc_charges持inventory共享，售后确认来源持inventory排他，不在已取后序锁时反向调用。台账聚合在同一锁事务投影。所有命令按tenant/actor/action/source/key，重放前再次检查对象关系与权限，输出再按当前字段权限裁剪。仅admin默认拥有新权限；基础device.read接口不要求service.read，售后/费用/资金增强独立请求，403清除增强数据。

不增加附件上传类型；人工报告/外部档案编号只登记引用，不产生公开URL或额外文件存储。已有文件保护不变。

## 迁移与限制

0015从0014增量升级，兼容既有安装数据和资金来源，保留老命令响应。PG17验证生成source_id表达式变更；不换数据库或清空旧表。有售后事实、安装或服务来源时拒绝降级；空新增域可降级恢复原表达式/权限。CNY、整数件数；不推定真实人工费率和厂商保修。

## 实施细化与验证发现

- 模板销售配置、原完工安装记录和当前有效安装分别展示。每个原安装事实分配稳定slot_id，历史事实只追加拆卸时间和更正关系；后继安装复用slot_id。诊断方案变更、换件、更正及重开都会推进验证代次，旧人工通过记录保留但失效。
- 成员表属于全局身份结构，不能假定它被业务RLS过滤。负责人列表与有效性检查显式使用当前租户；测试与浏览器记录了遗漏筛选的红测和修复。
- 创建/实物登记时间作为页面草稿字段保存，同次网络重试不重新生成时间或key。事务成功但响应丢失时回放原对象；显式新建才重置创建意图。页面和真实数据库分别验证，不混称。
- svc_dispositions追加旧件归还/有据报废，或RMA检验后隔离件的最终去向，禁止重复和既有RMA冲突。RMA“处置完成”指全部返回已做一次检验处置；选择继续隔离仍在旧件当前去向中显示hold，直到独立最终处置，不等于自动可售。取消的未发RMA可经service.correct显式重开原单，不能复用旧件创建重复活动RMA。
- 实际客户销售退货在存在活动售后工单时拒绝，要求先解决代管/处理责任；已有售后历史的发货事实不能直接误操作冲销。真实销售退货与售后归还各走自己的事实链。
- svc_works、svc_rmas、svc_reservations的来源字段由数据库触发器保护；冻结事件、领退、换件、费用、RMA送收检验和处置禁止覆盖/删除。预留只允许单调消费和释放。
- 修复路径不添加新的文件对象或引用表；档案编号不等于上传、下载或签名URL，不改变共享清理约束。
