# ADR-018 — 同源经营指标、历史日期与授权下钻

status: review_ready；TASK-013。编码前决策，继承ADR-015～017，不建立平行交易账。

## 决策

- 期间用上海自然日[start,end)，截止日用上海次日零点的排他上界；端点集中在analytics/time.py。默认按查询时已知事实重建历史业务日期，不提供“当时知道什么”的双时态承诺。
- 签约取冻结fields.signing_date；不存在时明确使用registered_at上海日期，名称说明。发货/误操作逆向按库存movement.effective_on；实际退货同原出库成本取退货movement。退款、实收实付按occurred_at；资金冲销/核销逆向/调整/更正/释放按事实created_at的上海日期。不拿当前reversed布尔值抹除历史。
- 未结项目需要可靠确认时点。0016增加不可变来源确认时间表（无金额/余额），数据库触发器记录未来fin_plans/cash/refunds的确认；已有记录仅从同事务成功确认审计回填，不能推断则标记历史不足。当前值仍按现有子台账规则查询。旧事实、金额及审查证据不改写。
- 每个报表请求先用既有会话/membership/预期企业认证，再沿catalog→quotes→CRM→inventory→finance共享锁读取。通过一个REPEATABLE READ事务在首次认证查询前建立数据库快照；不在相关查询之后补设隔离级别。并发会话变化引发序列化冲突时返回CONTEXT_CHANGED，不绕过授权。
- 图表与下钻共用后端同一投影。响应给出按当前授权、过滤条件和贡献明细计算的内容摘要；下钻重新鉴权重建投影，比对摘要。不一致返回REPORT_CHANGED并要求刷新整个报表，不能混用旧总额/新明细。无跨请求持久缓存，不保留撤权数据。
- 分批量读取必要事实，按ID索引内存关联，禁止每客户/每层调用详情产生N+1。SQL先按租户过滤；来源行级可见性在生成贡献行之前应用；前端只接收聚合与分页贡献行，不下载所有交易计算金额。查询记录数或范围上限必须显式拒绝，不能截断后声称完整。
- 入口使用analytics.read，来源区域另需crm.read/contract.read/delivery.read/finance.read/inventory.read/service.read；库存金额另需inventory.cost。只给admin新增入口权限；其他角色需要明确授予入口，不扩大资金/成本权限。负责人范围来自当前客户owner与采购/RMA负责人，与来源一致；库存来源缺少负责人粒度时 own 范围不展示全租户库存，返回范围不支持。
- 交易省份没有可靠结构化快照，签约与交付地区统一标记“按当前客户地区”。只精确匹配明确省名/标准代码及别名；海外仅显式海外标识，其他未知归入待完善。原创省级方格示意图不是行政边界或客户坐标，不上传地址；数据表永远可用，34省级单位+海外+未知合计守恒。
- 税口径不转换；签约按冻结报价已记录商业总额，必须显示其原口径，不称收入。标准DIO/DSO/DPO/现金转换周期因缺少完整会计/平均余额定义返回unavailable及缺项。只计算明确“完工到首次发货天数”等经营样本，同时展示未发样本数。
- 新地区/客户筛选对无法关联的库存或应付区域返回not_applicable，不能静默忽略；产品/品牌/业务负责人分析以冻结销售事实为基础，不借当前目录推断历史。

## 取舍和验证

租户共享锁与快照会增加写入等待；首期读同步、无后台报表系统。期间最多366天，下钻25默认/100上限、字段白名单排序。使用代表性多客户/多事实夹具测查询次数和计划；不声称大规模吞吐达标。无外部地图数据依赖，原创示意布置以可读性为先，不冒称精确地图。

真实PG验证半开时区边界、逆向时间归属、各聚合粒度不重复、RLS/行权限/成本裁剪、并发与摘要失效、迁移与原子确认。真实浏览器验证下钻、原业务详情、账龄库龄、不可计算说明、撤权/切企业及两视口。

## 实施细化

- 审计回填保留审计表与确认时间表的 FORCE RLS：逐个有效 membership 的租户上下文读取同租户成功确认审计。没有有效成员或可靠审计的旧租户不猜确认日期，恢复访问后历史仍提示资料不足。迁移末尾清空事务租户上下文，不关闭审计 RLS。
- 售后/RMA分析行范围继承其设备对应客户 owner；只有资金中的应付来源沿采购/RMA负责人校验，与 finance.source 一致。不要额外用售后工单 manager 缩小其原详情可见范围。
- RMA是否仍待处理由检验 disposition / 最终处置决定，不用 passed 布尔值代替实物状态：通过但 hold 仍计入，失败但已报废不计入。
- 前端刷新、重新激活、过滤变化均清除图表/提示/弹窗并递增请求代次；旧成功下钻响应不能重建弹窗，也不能让新报表永久处于明细加载状态。

## TASK-013 独立审查 R1/R2 修复

- 来源权限裁剪覆盖元数据：未授权指标的 basis 与 reason 均为通用说明；value、groups、贡献、下钻保持为空。名称/单位为静态指标定义，集中度N来自公开请求条件，不包含业务数量。动态样本说明仅对 delivery.read 授权结果生成输出。旧实现保留动态basis造成泄漏，本次修正。
- 明确期间现金流与余额截止日独立。收付款/退款以查询时已确认的真实来源事实及 occurred_at 进入[start,end)，各逆向按自身 created_at 进入期间；不使用as_of筛选确认日或逆向日。原款在前期、逆向在本期时，本期保留负向贡献。
- 期间现金流不需要推断过去何时确认：当前confirmed状态与不可变发生日足够证明已知事实；事后登记仍归发生日期。缺少确认时间元数据不影响这一口径，也不因无关计划的历史缺失而将期间现金流标为不可计算。未确认草稿永不进入。
- 截止日余额继续使用确认时间、核销、逆向及调整时间重建，缺确认时间的保守不可计算/部分状态不变。不修改原资金、确认时间或发布快照；测试对历史日期的准备只在独立夹具中进行。API筛选条件不联动、不限制as_of到期间末。
