# ADR-011：人工审批、不可变发布与来源合同草稿

状态：TASK-006 review_ready，按本轮明确任务决策实现，等待独立审查。

## 阶段性政策

继承 ADR-010 的 CNY/价格表含税口径、Decimal HALF_UP 顺序、单码百分比。成本、利润、贡献率、拆分税额、运费和服务费未知，不填写零，也不采用 Demo 的20%阈值。全部候选均需人工审批，提交人与审批人必须不同。全局 data-model 中次数/预算额度预留、核销尚未实现；本期 policy.discount_quota 只能 unlimited，limited 明确拒绝。没有外发、PDF、签约、库存或采购。

publication_policies 由受信任操作员按 catalog共享→quote排他锁显式配置，包含身份、版本、启停、development/formal、风险放行责任、额度能力标识。开发种子仅独立测试栈装入；无政策禁止提交发布。正式政策需明确责任资料，不能使用开发标记冒充正式商务。开发标记进入冻结内容并复制合同。报价的 sale_ready=false 保留，不能作为新的发布授权布尔；新门槛逐层检查金额、BLOCK、风险确认、审批与政策有效性。

BLOCK 一律不允许人工覆盖；WARN/UNKNOWN 原状态保留，仅在政策 allow_risks 且审批人逐项填写说明和依据时批准。本期政策确认、成本未知、费用未配置各自保留风险项。审批页展示完整配置、金额来源、规则及风险，不只是总额。无第二人时保持待审批，自批始终拒绝。

## 事实与状态

0007_publication 增加 policy、candidate、decision、quote_version、version_state、event、contract_draft、command。candidate 冻结草稿版本及配置、客户/项目必要展示信息、完整 BOM/规则快照、当前选中规格与计价、价格/折扣条件、有效期、政策及未知字段。稳定 hash 排除 calculated_at、观察价格 as_of 和已含这些时刻的 fingerprint；有效期先规范 UTC。时间经过本身不变 hash，跨价格、优惠或报价有效期仍实时拒绝。

草稿记录当前 candidate 指针；重新提交（包括变更有效期）会使之前未发布候选失效。草稿编辑 version 变化同样失效。candidate/decision 历史不改；有效状态由当前版本、指针、依赖及参与者权限判定。发布后草稿拒绝原位保存，必须从发布内容创建独立修订草稿，来源链保留、旧审批不继承。

decision 唯一 candidate，保存审批者、结论、说明、风险说明/依据及时间。发布在同事务重算/比对哈希/检查参与者权限；不替换已批准价格。一个 candidate 只能发布一次，不同key返回同一版本。编号租户内顺序生成，受quote排他锁及唯一约束保护；撤回只改变独立 state 并追加事件，冻结内容不变。有效期 [issued_at,valid_until)，消费入口实时检查。

candidate、decision、quote_version、contract_draft、events、command 仅赋予运行角色 SELECT/INSERT，无 UPDATE/DELETE，另有不可变触发器保护。全部新表 FORCE RLS/tenant_visible；关系采用租户复合 FK。发布父内容、审批引用、发行时间与正文保持；策略/客户/商品以后变化不更新冻结对象。

合同源版本唯一约束与命令防重同时生效；只能从有效且当前可见的版本复制 Frozen 内容和hash，不调计价器。合同source访问检查冻结客户，不因草稿引用变化重定向。CRM 联系人、项目、地点、已配置负责人及姓名按来源复制；地点不冒充注册地址，未配置乙方法人不猜。草稿保留复制时间及不可变发布引用；源撤回/过期只提示，不删除合同。完整编辑、签约和付款节点属于 TASK-007。

## 权限、重放与锁

quote.submit 对 admin/member，quote.approve/issue/withdraw 对 admin，contract.create 对 admin/member、contract.read 对全部已有角色；仍要求当前客户数据权限。内部审批说明/依据只在有 quote.approve 的候选详情中返回，普通发布/合同商业内容没有内部说明或原始折扣码。幂等记录保存结果id，重放重读并重新验证当前操作权限/客户访问，不能返回缓存越权正文。

HTTP 先锁会话验证CSRF/context和调用者membership；新增生命周期事务在 catalog/quote 之前按稳定UUID顺序取得本企业当前有效参与者的 membership/identity 共享锁，建立参与者权限映射；不在 quote/CRM 后重新请求 membership 锁。共享锁彼此兼容，停用/角色变更等待事务完成。现有身份维护只操作身份表，不反向取业务锁。首期为简化锁序对当前企业全部有效成员取共享锁，规模优化须保留同一授权语义。

随后 catalog共享→quote共享读/排他写→CRM父共享。复用旧报价guard，发布/审批/编辑/撤回/转合同按此排序；所有数据/审计同事务提交。目录写只取catalog，CRM写不进入quote；不增加反向锁。测试用屏障和有限等待验证竞争，运行角色验证RLS。操作员直接改政策/优惠需按相同guard维护，SQL不是公开产品入口。

## 证据边界

任务书要求真实PG/API、空库及0006升级、真实OIDC/两人浏览器和原相关回归；结果以 TASK-006/result.md 为准。原生产拒绝启动保护保持，不把开发发布或本地通过等同生产上线。

修订版本沿来源根编号生成 Q-000001-R2 等后缀，分支修订也由租户quote锁分配单调revision；冻结审批/发布引用通过不可变关系表保留，不把敏感审批说明复制到普通商业正文。

## 具体接口

命令统一 `/api/v1/publication`，避免将候选id与草稿id混同：`drafts/{id}/submit`、`candidates/{id}/decide`、`candidates/{id}/issue`、`versions/{id}/withdraw`、`versions/{id}/revise`、`contracts/from-quote`。列表/详情为 `candidates`、`versions`、`contracts`，首期最多100项按创建时间/id稳定排序。所有命令POST、CSRF、上下文、幂等；提交/决定/发布expected_version为所绑定草稿版本，撤回/转合同/修订为发布生命周期版本。OpenAPI为精确有类型契约。

有效性检查错误区分 PUBLICATION_POLICY_REQUIRED、PUBLICATION_HARD_BLOCK、RISK_CONFIRMATION_REQUIRED、APPROVAL_INVALIDATED、PARTICIPANT_ACCESS_CHANGED、SOURCE_NOT_ACTIVE；前端保留用户输入并解释下一步。收到审批失效错误立即移除旧发布控件，仍可刷新历史内容。未登录/权限/不可见对象/缺失或旧上下文继续沿用401/403/404/428/409。
