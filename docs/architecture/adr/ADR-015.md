# ADR-015 — 测试有效性与实物交付事实

status: review_ready；TASK-010。

## 现有来源及限制

sales_orders 是签约时冻结的一条整机配置及 quantity 台数，尚无独立多配置 sales_order_lines。本轮以该订单的单一冻结配置作为现有订单行，del_lines.order_id 复合外键绑定，不另建销售订单或根据现价重建配置。设备必须是同订单 asm_work 产生的稳定 asm_device，产品身份取该工单确认的成品 SKU，不要求成品SKU与原准系统SKU相同。当前无脱离装配的第三方成品建档入口；已有第三方品牌成品按同一完工来源验证，无设备档案/有效完工的采购实物不会进入可选设备。本轮不虚构第三方收货自动建档能力。

## 锁和命令

身份/会话/membership → catalog共享 → quotes共享 → inventory租户共享读/排他写，与装配、预留、文件清理一致，不增加反序锁。单租户写串行是吞吐取舍，聚合持共享锁读完；竞争先取得锁的事务决定顺序。确认事务检查订单剩余、设备、测试、位置、有效预留后记录同一库存台账；没有中间提交。草稿不占实物，确认后库存为零，第二个请求不能再次发出。所有命令重放前重查当前权限/上下文/来源对象；inv_commands 作用域含tenant/actor/action/source/key。成本按当前权限裁剪重放响应。

## 测试与资格

人工测试是追加事实，执行人员由服务端当前actor确定，执行时间不得未来。items非空且同名拒绝，任何fail使整次fail；按数据库接收顺序取最后记录，不因回填较早执行时间让旧通过继续生效。测试绑定有效 completion_id 及本次推进后的 inv_layer.version；完工更正、移库、发货、退货使版本变化，必须复测。测试本身不伪造硬件自动采集或客户验收。

库存的pending为生产完工/退回的物理待检存放状态；有效人工测试通过是该件受控发货的放行依据，不将普通pending库存开放为装配可预留量。qualified也仍须有效测试，quarantine禁止发货。报告/验收证据字段为人工档案登记编号，不是文件下载URL，不添加文件存储引用或绕过共享清理保护；记录本身可追溯操作者及时间，完整测试报告上传管理不在本轮入口中冒称已实现。

## 不可变交付与成本

发货草稿的选择/收货资料固定；误选取消新建。确认时逐行补入实际完工、成本层、测试和出库移动引用，随后冻结。version只负责后续命令竞争。设备数量每行一台；确认用原层出库-1，原层NUMERIC成本不可变，不使用当前采购/目录价；退货+1回同一层的指定待检库位，引用原行/移动就是成本逆向依据。验收不产生库存移动。命令审计保存动作、对象、actor、tenant和request_id；现有系统尚无交付外部消费者，本轮不新增空跑通知job或冒称发送。

已确认发货永不删除；误操作仅整批显式冲销且无任何验收/退货下游，库存恢复pending并失去旧测试。真实退货逐行唯一、实收确认才入库；保留所有原安装和设备ID。装配逆向遇任何已过账交付历史均拒绝，防止更正破坏已存在的履约事实，即使净交付为零也不能抹除来源。

验收按实际行登记；更正追加accepted=false及corrects关系，链尾决定当前验收状态。退货后拒绝再改原验收，将历史验收和净验收分开。累计发出排除误操作冲销、保留真实退回；净交付=累计发出-退回；剩余=订单台数-净交付，默认恢复待履约。净验收扣除已退回；退款、终止剩余履约未实现。新一次发货创建新行，旧发货/验收/退货不覆盖。

## 迁移

0012仅新增交付表、权限及库存移动种类，不改旧快照、不清空数据。全部租户表 FORCE RLS、复合外键，冻结触发器保护过账内容。只有交付表均空才允许降级；存在历史则拒绝整个降级事务。恢复采用正常备份恢复流程，不能删历史来迁移。

## R1 修复：基础设备与交付查询分层

`device.read` 继续授权 `/assembly/devices` 的列表、搜索和详情，不隐含 `delivery.read`；装配页面不等待交付请求。设备页面基础数据仅从原设备接口取得，打开详情后按 `delivery.read` 加载独立交付增强状态。刷新、搜索、重开/关闭详情先清除旧增强状态；403 明确显示未授权并保留基础信息，其他失败显示真实错误，不用空历史冒充成功。请求代次及企业上下文拒绝关闭或切企业后的迟到成功响应。基础接口的历史 `delivery_state=not_started` 不是当前履约事实，页面不据此声称未发货。

保持已有服务端授权和字段口径，不扩大默认角色：`delivery.read` 单独授权交付模块的 `DeliveryDeviceView`，包括同租户设备/SN/型号/品牌、客户/订单/合同/报价/项目标识、库存位置、安装与完工来源，以及测试/发货/验收/退货历史，用于履约追溯；该权限不授予 `/assembly/devices`、工单查询/写入、采购或附件访问。它是已有交付投影的明确读取权限，不等同于所有设备域操作权限。两类投影中的成本均另需 `inventory.cost`，关联对象的 ID 也不授予该对象接口访问。此次不增加任何响应字段，不改 API、迁移、锁序、冻结快照或写命令。真实 PG/API 回归固定上述独立权限组合、撤权、跨租户和成本裁剪。

未纳入本次 R1 的建议：从出库移动投影确认发货时间。当前草稿创建时间不能冒称确认发货时间，留待单独产品安排。
