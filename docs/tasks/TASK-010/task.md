## 业务闭环

完工待检 → 测试 → 同订单分批发货 → 按具体已发设备部分/全部验收 → 部分/全部实际销售退货 → 待检复测 → 再发货。设备、库存、履约、成本历史均由真实后端持久化。

### 设备测试

测试绑定稳定设备 ID 和具体有效 asm_completions；现有支持的第三方整机须绑定明确入库/检验来源，不能因无工单无条件放行。记录测试项、结果、执行人员、时间、备注和可追溯报告引用；区分待测试、通过、不通过。后端从记录判定资格，不接受前端直接改资格。失败后复测追加，后续失败使旧通过失效。完工撤销、更正、影响配置的变更和销售退货后，旧测试不能赋予新状态资格。

### 分批发货

使用现有同租户有效销售订单/订单行，按实际设备/SN 选择。显示本次、累计和剩余。后端验证订单资格、产品匹配、实物存在、可用库位、有效测试、无有效冲突预留/已发、剩余额度和跨租户引用。确认事务原子记录发货明细、库存出库、预留处理、设备状态、原成本事实、审计及既有事件机制所需记录。并发同设备只能一次，幂等不重复出库/成本。冻结收货单位、地址、联系人。草稿可取消；已确认不可删单恢复库存。误操作冲销与真实退货分开，有下游记录阻止直接冲销并提示原因。

### 交付验收

必须关联真实发货明细和设备，支持部分验收；记录时间、经办人、客户确认资料、备注/证据。拒绝未发、重复和超量；不再次扣库存或结转成本。更正追加关系，不覆盖历史；页面区分发货、验收、收款，不虚构收款。

### 销售退货

关联原发货行及稳定 ID/SN；不得超过尚未退回数量。确认表示实际收货，申请本身不得加库存。退回待检/隔离，不能自动可售或测试合格。保留设备、配置、安装；逆向原出库成本，不使用当前价格；并发/重复只能一次。已发、已验收、退回、净交付、剩余均从明细计算且非负。默认恢复待履约数量，再交付必须重新满足库存及测试资格；退款、终止剩余履约、完整换货留后续。
