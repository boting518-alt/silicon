二、本次业务闭环

从已发布报价生成的合同草稿出发：

完善甲乙方与责任人员
→ 配置付款节点
→ 上传合同及关联附件
→ 查看签约前校验与待冻结内容
→ 授权人员登记线下签约
→ 冻结合同版本并生成销售订单
→ 刷新查看合同、订单与原报价的追溯关系。

这是“线下签约事实登记”，不是电子签章服务。
系统登记成功不代表完成电子签名、收款、开票、交付或收入确认。

三、合同草稿完善

沿用 TASK-006 的合同草稿和来源报价版本，不另建平行模型。

甲方信息：
- 单位名称；
- 地址；
- 项目负责人；
- 关键联系人，可多名；
- 联系方式，按权限展示；
- 可选统一社会信用代码等主体标识。

乙方信息：
- 单位名称、地址及可选主体标识；
- 销售负责人；
- 售后运维负责人。

合同信息：
- 合同名称、内部唯一编号；
- 来源报价编号、版本及快照 hash；
- 币种、含税/不含税口径、合同金额；
- 签约主体与签约日期；
- 约定交付日期或交付说明；
- 付款节点及必要商务备注。

要求：
- 从来源复制到草稿的字段可以按权限完善，保存 expected_version。
- 主数据后续变化不得静默覆盖草稿已明确填写的值。
- 内部责任人保存账号引用与姓名等展示值。
- 停用人员历史可查，新分配应检查当前成员资格。
- 客户联系人不等于内部员工，不混用身份表。
- 不把当前登录人自动认定为销售、运维或签约代表。
- 缺失字段显示待补齐，不虚构名称、地址或联系人。

四、商业内容保持一致

本轮合同的设备配置、数量、价格、折扣、总额和币种口径，
沿用来源发布报价的冻结商业内容。

- 不允许在合同编辑页任意改总价或替换设备。
- 商业内容需要改变时，提示返回报价修订、审批和发布流程，
  再由新发布版本生成新的合同草稿。
- 甲乙方信息及非金额商务条款的完善属于本轮范围。
- 不把“同一项目的新报价”静默替换为原合同来源。
- 保留 TASK-006 开发政策/演示数据标识，并向签约登记及订单继承。

展示销售设备：
- SKU、型号、制造商；
- 品牌及自有/第三方属性；
- 数量和商业行金额；
- included 部件明确含于包件，避免重复金额。

同时保留商业行与技术配置的关联，不能将两者混为同一计费清单。
本轮没有设备 SN、实际安装关系或资产库存，不伪造设备档案。
后续售后查询可先从合同/订单追溯销售配置，实际设备档案由后续任务建立。

五、付款节点

付款节点是合同约定，不是实际应收、收款或核销记录。

首期按固定金额保存：
- 节点名称；
- 正金额；
- 到期方式；
- 已知到期日期，或触发事件及偏移天数；
- 备注与展示顺序。

要求：
1. 使用 Decimal/NUMERIC，API 金额使用精确字符串。
2. 节点金额合计必须等于合同金额，币种一致。
3. 可提供百分比辅助输入，但持久化金额及尾差分配必须确定、可解释。
4. 触发事件尚未发生时，到期日为空且显示“待触发”，不猜测日期。
5. 草稿允许暂未配平，但签约登记必须阻断。
6. 本轮仅支持付款计划：
   不生成收款流水，不自动标记已收，不实现核销、发票或收入确认。
7. 已签合同中的约定节点不可原位更改；后续实际履行状态单独建模。

六、附件

支持合同草稿及合同版本关联附件：
- 合同文件；
- 签约证明材料；
- 技术配置附件；
- 其他明确分类的业务附件。

使用现有附件架构；若尚未实现，建立最小私有文件存储接口：
开发环境可使用受控目录适配器，不硬编码用户机器路径，
不引入未经配置的公开存储服务。

必要字段：
- tenant_id、附件 id、原始展示文件名；
- 服务端生成的存储标识；
- 实际大小、检测到的媒体类型、SHA-256；
- 上传人、上传时间、所属对象；
- 用途分类及生命周期状态。

要求：
- 上传、列出、下载、关联和删除都检查租户与对象权限。
- 不使用用户提供的路径作为磁盘路径。
- 文件大小、扩展名与内容类型均进行服务端校验；
  本轮限定 PDF/JPEG/PNG，具体大小上限写入配置和文档。
- 下载通过鉴权接口或短时受控凭证，不能公开静态目录。
- 不直接以内联 HTML/SVG 等主动内容展示附件。
- 浏览器声明的 MIME 不作为唯一依据。
- 不把文件类型检查宣称为恶意软件扫描；扫描未配置应如实记录。
- 上传失败、关联失败及数据库事务回滚不得产生可见的半完成附件。
- 明确临时上传与正式关联流程，提供受控孤儿文件清理方案。
- 草稿附件可以按权限删除；已签版本引用的文件内容和元数据不可替换。
- 新增补充材料使用新记录，并明确不属于原签约冻结附件集。
- 文件签名、内部路径及下载凭据不得泄露到普通日志。

七、签约登记与冻结

首期要求：
- 授权人员明确确认“已在线下完成签约”；
- 填写签约日期和必要签约主体信息；
- 至少关联一份签约证明材料；
- 服务端校验付款计划、来源资格和附件就绪状态。

已知硬性阻断：
- 必填主体或责任人信息不完整；
- 商业内容与来源发布报价不一致；
- 付款金额未配平；
- 缺签约证明或附件尚未就绪；
- 来源报价已撤回或过期；
- 当前权限、租户或版本已变化；
- 正式政策未配置却试图执行正式业务登记。

本轮不支持追溯性例外审批：
即使填写的线下签约日期早于报价过期时间，
若当前来源已过期，仍阻断新登记，并提示后续处理路径。
如业务需要例外，应另立明确政策，不增加隐藏绕过开关。

冻结内容：
- 合同编号及版本；
- 甲乙方主体；
- 项目负责人、关键联系人；
- 内部销售及运维责任人历史展示信息；
- 商业行与技术配置；
- 金额及币种口径；
- 付款约定；
- 交付约定；
- 签约附件清单及文件 hash；
- 来源报价版本/hash；
- 签约日期、登记人及登记时间；
- 开发/正式政策标识。

签约命令：
- 绑定 expected_version、当前内容 hash 和幂等键；
- 明确当前用户确认的就是本次被冻结内容；
- 数据库层保护已签内容，运行角色不能原位更新或删除；
- 主数据变化不改写历史；
- 本轮不实现已签合同变更、解除、作废或退款流程；
  界面说明需后续受控变更，不提供直接编辑已签版本的入口。

八、销售订单

签约登记成功后生成一份销售订单：
- 本轮一个已签合同版本对应一个销售订单；
- 数据库唯一约束与命令幂等共同防重；
- 关联合同版本和原报价版本；
- 订单商业行来自冻结合同，不重新取当前目录价格；
- 保存技术配置的来源关联，included 不重复产生收入金额。

合同冻结、订单创建及必要审计应在一致的事务边界内完成。
失败时不能出现“合同已签但订单丢失”的半完成状态。

订单初始状态为待履行；不占库存、不采购、不发货。
分开展示：
- 合同签约状态；
- 订单履行状态；
- 付款计划；
- 实际收款、开票、发货与验收：本轮未接入。

不要用一个“已完成”状态代表上述全部业务。

九、权限与并发

复用现有登录、租户上下文、RLS、CSRF、审计和请求代次机制。

默认权限：
- member/admin：维护其有权访问客户的合同草稿及附件；
- admin：签约登记；
- viewer：只读其有权访问的数据和允许下载的附件。

服务端使用独立权限项，不只依赖前端角色判断。
内部审批说明及成本信息不得因进入合同页而扩大可见范围。

必须处理：
- 并发编辑合同；
- 编辑与签约竞争；
- 签约与附件删除/替换竞争；
- 签约与来源报价撤回竞争；
- 重复签约和不同幂等键重复请求；
- 权限变化后的历史请求重放。

在新 ADR 中明确与现有锁顺序的关系，避免反向锁与死锁。
所有跨对象引用采用租户复合约束。
