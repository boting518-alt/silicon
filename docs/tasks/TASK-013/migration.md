# 0016 迁移与恢复边界

从仓库根按现有环境变量加载方式执行 `python infra/migrate.py upgrade head` 和 `python infra/migrate.py current`。生产模式拒绝启动保护继续保留；本任务不部署或操作常驻数据库。

迁移新增 `analytics.read`（仅 admin）、四个来源查询索引，以及 `analytics_confirmations`。该表只存来源ID/确认时间和回填来源，不存金额、余额或经营结果；复合外键校验同租户真实来源，FORCE RLS 和不可变触发器保护历史。未来资金确认由同事务触发器记录，失败事务不会留下时间记录。

已有确认时间只从同事务成功的 `finance.plans.confirm:<id>` / `finance.cash.confirm:<id>` / `finance.refunds.confirm:<id>` 审计回填。不以创建时间推断。找不到审计的旧事实可查询当前值并提示部分时间缺失；历史截止日明确不可计算。迁移不改原业务金额或已发布内容。

若已有新的 transition 时间记录，降级被拒绝，以免丢失精确确认时间；使用向前修复。只有尚无 transition 记录时允许删除该分析元数据和索引，原业务与审计保留；再次升级可重建 audit 来源时间。执行前按既有运维流程保存数据库备份（备份不进入审查包）。空库及保留0015身份/合同/资金事实的升级均由隔离集群测试。

为继续验证更早的0013→0014升级，原资金更正测试现在在创建旧事实之前先退到0015；之后原有更正/历史不变断言保持。该调整属于旧模式夹具准备，不绕过0016对真实新记录的降级保护。

回填查询不关闭审计 RLS，使用当时仍有效的成员上下文逐租户读取；没有有效成员的租户会缺少回填，后续查询按照既定“历史资料不足”规则呈现。该限制不影响原业务事实和审计保留。
