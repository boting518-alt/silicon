## 3. 本次范围

### 3.1 装配工单与冻结配置

装配工单关联既有销售订单及其冻结商业、技术配置，不重新读取当前价格替换历史内容。

首版：

* 一个销售订单允许多个装配工单。
* 一个装配工单对应一台成品设备。
* 多台设备拆成多个工单，服务端防止累计计划数量超过订单。
* 工单记录计划成品 SKU、内部负责人、计划日期及备注。
* 工单需求明确区分准系统、独立部件、已包含部件和非实物商业行。

**不得重复展开准系统中的 included 部件。** 例如一个带电源的准系统按一个库存 SKU 领用，不能再凭技术展示行额外扣减电源。

在 ADR 中明确冻结配置到实际领料需求的映射。无法确定映射时显示具体缺口并阻断执行，不按名称猜测 SKU。

本轮不支持物料替代或临时改变销售配置；需要变更时回到既有报价、合同处理流程。

建议状态：

| 状态          | 含义             |
| ----------- | -------------- |
| draft       | 工单资料及需求待确认     |
| ready       | 需求已确认，可以预留     |
| in_progress | 已发生领料，物料进入在制   |
| completed   | 已完工并形成设备与成品库存  |
| cancelled   | 未领料工单已取消，预留已释放 |

预留是否齐套单独表达，不用一个状态混合工单进度与物料准备情况。

### 3.2 库存预留

预留关联工单需求、销售订单和实际库存来源。

可预留范围：

* 本企业自有库存。
* 质量状态合格。
* 尚未领用、尚未被有效预留占用。
* 物料 SKU 和追踪方式符合工单需求。

待检、隔离、客户代管、已领入在制的物料不能预留。

支持：

* 按需求数量部分预留。
* 显示已预留、缺口及实际来源。
* 主动释放剩余预留。
* 未领料工单取消时原子释放预留。
* 预留过期后的释放及审计。

预留不产生库存数量移动，也不产生费用或销售成本。

SN 件按物理件预留；批次件按成本层与数量预留。批次选择遵循既有 FIFO 顺序，允许早期层中被其他有效预留占用的部分暂不可分配。

预留时固定来源，领料时不得静默改取另一成本层。

如使用到期时间：

* 使用明确时区的服务端时间。
* 到期预留不能继续被消费。
* 过期释放和领料必须经过相同事务保护。
* 即使 Worker 暂时未运行，也不能让到期预留被重复占用或错误消费。
* 定时清理复用既有 Worker，不另建调度系统。

### 3.3 领料与在制库存

领料只能消费当前工单有效预留，不能绕过预留直接扣库存。

支持一次或分批领料。每次领料记录：

* 工单、需求行和预留来源。
* SN 或批次成本层。
* 数量。
* 来源库位及在制位置。
* 操作者、时间、幂等键与业务原因。

同一事务内完成：

1. 校验工单、预留、库存及版本。
2. 扣减来源库存。
3. 增加对应工单在制数量及成本。
4. 更新预留已消费量。
5. 写入不可变移动、审计及必要事件。

在制物料不再属于可销售零件库存。已领用 SN 不能继续预留给其他工单。

未知成本允许保留在原库存，但本轮禁止领入装配；返回具体缺成本来源，不能按零成本放行。

### 3.4 完工、成品与成本连续性

完工前必须满足：

* 工单需求映射完整。
* 所需物料已足量领用，无重复或超领。
* 成品 SKU 已明确，采用 SN 追踪。
* 成品 SN 合法且不存在冲突。
* 部件与槽位关系符合工单需求。
* 在制成本完整。

首版成品成本为：

**实际领料成本合计。**

本轮不加入人工、运费或其他新增费用分摊。页面明确显示成本范围，不能称为完整经营利润或最终全部制造成本。

完工在同一事务内：

* 结转工单在制物料与成本。
* 创建一件成品库存实物及其成本来源。
* 创建设备档案。
* 记录部件安装关系。
* 将工单更新为 completed。

成品进入**待测试/待检状态**，不自动进入可发货状态。后续测试及交付由 TASK-010 处理。

不得同时保留以下三份库存金额：

* 原零件库存成本；
* 已结转在制成本；
* 成品库存成本。

设备档案引用成品 `inventory_unit`，不能再创建第二份代表同一整机的库存。

### 3.5 设备档案与部件追溯

设备档案至少包含：

* 内部设备编号、整机 SN。
* 成品 SKU、型号、制造商、品牌及自有/第三方属性快照。
* 来源工单、销售订单、已签合同及报价版本。
* 关联客户和项目。
* 完工时间、当前库存状态及位置。
* 部件配置、安装关系及成本来源引用。

客户/项目关联表示计划履约来源，不代表客户已收货或拥有设备。实际部署地址、发货日期和验收日期在本轮保持未发生。

部件安装记录：

* SN 件引用原物理件 ID，保留原 SN。
* 非序列化件引用批次/成本层及数量，不虚构部件 SN。
* 保存槽位或明确的配置位置。
* 保存安装时间、拆卸时间、来源工单和更正引用。
* 同一 SN 部件不能同时有效安装于两台设备。
* 保留原物理身份和成本来源，不能覆盖旧记录模拟换件。

支持按整机 SN、部件 SN、型号、客户、合同或订单查询。

查询先执行租户和数据范围授权，再返回结果；运维可查询配置与来源，不因此默认获得采购成本。

### 3.6 取消与错误更正

首版支持：

* 未领料工单取消并释放预留。
* 错误领料按整次领料记录逆向，前提是对应物料仍完整处于该工单在制状态。
* 错误完工按整次完工记录逆向，前提是成品未发生后续测试、预留、移库、出库或其他依赖。

逆向必须关联原记录、原因、操作者和时间。重复逆向或超额逆向拒绝，不能删除原台账。

完工逆向应恢复对应在制数量和成本，关闭原安装关系，保留设备及安装历史；不能把原部件当成新购入物料。

本轮不实现正常售后拆解、换件、返工生产或销售退货。发现后续依赖时返回阻断记录，不强制更正。

## 4. 对账与既有功能整合

扩展库存查询与对账，明确展示：

* 原料/零件库存。
* 工单在制。
* 成品库存。
* 有效预留及可用数量。

预留不改变账面库存成本；领料和完工是成本位置转换。

**原料减少成本 = 在制增加成本；在制结转成本 = 成品增加成本。**

对账支持从工单或设备下钻到领料、预留、入库成本层和采购来源。差异必须可定位，不能自动改余额“对平”。

## 7. 必须验证的场景

数据库与并发语义使用真实 PostgreSQL：

1. 两个工单并发预留同一 SN，只能一个成功。
2. 批次库存部分预留，累计预留不超过可用数量。
3. 到期释放、主动释放与领料竞争不重复消费。
4. 部分领料后取消或释放，不影响已消费记录。
5. FIFO 来源与固定预留层保持一致。
6. included 部件不重复生成领料需求。
7. 不合格、客户代管、未知成本或库存不足时阻断。
8. 领料和完工数量、成本守恒，无重复计价。
9. 重复完工及响应丢失重试只产生一件成品和一份设备档案。
10. 同一部件不能同时安装于两台设备。
11. 领料、完工逆向恢复正确；存在后续依赖时拒绝。
12. 已预留/已领料对象不能被旧库存接口绕过保护。
13. 跨租户、成本权限、撤权重放及后台过期处理权限有效。
14. 空库迁移及 TASK-008 数据库升级保留已有数据。
