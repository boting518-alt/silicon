## 4. 本次交付范围

### 4.1 供应商与采购单据

实现供应商基础资料：单位名称、地址、联系人及联系方式、状态。继承现有租户隔离和可见范围。

采购合同包括供应商、我方主体、内部采购负责人、编号、币种、签订日期、交期、备注与来源附件。生效时冻结双方及商业条款快照；后续主数据编辑不改写历史。

采购订单必须能够关联采购合同，一份合同支持多张订单，一张订单支持多行与分批到货。采购订单行绑定既有 SKU，记录数量、单位、单价、税口径、交期及可选销售订单/项目来源。通用备货允许不关联销售订单。

合同商业行与订单行建立可核对关系，禁止重复下单导致合同数量/额度超限；需要增加额度时通过显式合同变更，不静默超采。首版不支持脱离采购合同的自由采购订单。

供应商确认编号可记录但不等于外部发送成功。不接电子签章或供应商门户；复用 TASK-007 附件机制及授权下载，避免另建附件系统。

合同草稿可编辑，生效后冻结。订单确认后冻结商业内容；未到部分可显式取消，已到部分保留。交付进度从净到货数量计算，不能由前端任意改成“已完成”。

### 4.2 仓库、库位、所有权与追踪方式

实现仓库和库位，并支持待检、合格、隔离的显式库存状态。状态和实物位置分别可追溯。

库存明确区分自有和客户所有/代管：客户所有库存不能计入自有账面成本或可供履约数量。本次采购入库默认自有；期初允许登记客户所有库存并明确所有权。

沿用既有 SKU，不再创建第二套商品目录。SKU 指定 SN 或批次追踪，发生库存交易后不允许随意切换追踪和成本方法。

- SN 件：一件一个 inventory_unit，数量为 1；保留原始 SN 和内部 ID。依据租户、厂商/型号及标准化 SN 建唯一约束，不假设全球 SN 唯一。
- 非序列化件：按批次及入库成本层追踪数量；相同外部批号不应合并掉不同到货成本。
- 标准化规则须文档化；禁止未经依据将大小写、标点等差异全部抹掉而误合并。
- 收货、质检、移库和冲销均复用同一物理件身份，不复制 SN 实物。

### 4.3 分批收货与质检

支持采购订单分批、分行到货，记录实际到货时间、操作人、仓库/库位、数量、SN/批次及送货凭证。收货草稿保存不影响库存；收货过账才创建库存台账及成本层。

首版禁止超订单净剩余量收货；取消未到部分后同步减少允许收货量。数量校验考虑历史收货及有效冲销，必须防并发超收。

收货先进入待检，不自动计为可用。质检支持部分合格、部分隔离；例如 5 件到货可分为 4 件合格、1 件隔离。SN 行按实物选取，批次行按受控数量拆分。

保存质检人、时间、结论和原因。SN 类商品未提供完整、合法且不重复的 SN 不得过账。

合格入库后刷新仍能查询实物、批次、采购来源与移动记录。待检、隔离、在途及客户所有库存不能被可用量接口返回为可用。

### 4.4 库存移动与更正

移动台账是数量事实来源，stock_balance 是事务内维护的投影。实现以下显式移动：期初入库、采购收货、质检转合格、质检转隔离、内部移库、错误过账冲销。

内部移库/状态转移必须成对记录，源扣减与目标增加在同一事务提交；数量及成本守恒。禁止直接覆盖余额，禁止负库存，禁止同一 SN 同时出现在两个有效位置。

已过账记录不可编辑或删除。更正以关联原记录的逆向记录完成，保存原因、操作者、时间与请求 ID；重复冲销或累计超额冲销必须拒绝。首版可以只支持整张错误单据冲销，但必须在 UI 和接口明确这一限制。

若原收货已发生质检或移库，应按可逆依赖顺序恢复后再冲销，或拒绝并返回具体阻断记录；不能强制删除后续台账。正常采购退货、退款、报损与盘点差异不借用“错误冲销”冒充，本次保留后续扩展接口设计，不实现其业务流程。

### 4.5 成本记录与对账

继承既定策略：SN 件个别计价；非序列化件保存 FIFO 成本层与稳定排序依据。此任务建立入库成本、成本携带和逆向恢复，不提前实现销售出库 FIFO 消耗或销售成本结转。

金额使用 Decimal/NUMERIC，API 用字符串表示。数量精度按商品单位明确校验；逐件设备不接受小数数量。

成本需记录原始单据、成本确认依据、币种、税口径、发生时间及状态。采购含税金额、可抵扣税额、计入库存的成本分别表达；不硬编码统一税率或自动推定可抵扣资格。

首版限定单一配置的记账币种，拒绝未支持的外币交易，不暗中按 1:1 换算。未配置的税费政策保留为待确认；可使用明确标注的测试政策验证功能，不把测试假设包装成正式财务规则。

收货时采用有出处的暂估或已确认成本，二者明确区分。缺成本时允许记录实物，但必须标记 unknown、列出缺成本数量；禁止把未知成本当 0 或把已知部分汇总显示成完整库存金额。缺成本实物不允许进入会消耗成本的后续动作。

本次不支持向历史已过账成本层追加分摊费用或发票差异重估；发现原值错误时遵循受限逆向更正流程。运费等无法可靠分配时单独记录待处理，不随意摊入库存。

提供库存数量与成本对账查询：

- 截止时点按 SKU、仓库/库位、状态、所有权、SN/批次下钻。
- 数量：期初 + 外部入库 − 有效逆向 = 期末；内部转移全局净额为零。
- 成本：已知成本的期初 + 入库 − 逆向 = 已知成本期末；内部移动成本净额为零。
- 数量与成本投影能够同台账重算值比较；差异应可定位，不自动抹平。
- 有未知成本时给出“已知成本小计 + 待确认数量”，总成本标记不完整。

### 4.6 基本期初导入

支持 CSV 模板下载、上传预校验、预览、明确提交与结果明细。至少包含外部行标识、SKU、仓库/库位、库存状态、所有权、数量、SN/批次、单位成本或未知标记、币种、期初日期和依据。

校验跨租户引用、重复行/SN、未知 SKU、非法数量、币种/日期与成本口径。首版采用整批原子提交：任意行错误则不产生库存事实；重试不得重复入账。

导入内容哈希及业务行身份同时防重，不能靠换请求键或调整 CSV 行序绕过。相同内容重放返回原结果；确属不同批次的新数据须有明确外部身份。

定义期初截止日和首次业务过账边界，避免同一资产既导入期初又作为后续收货入账。期初流程结束后关闭普通导入入口；再次开放需要显式权限、原因和审计，禁止任意回填历史。

保留原始文件版本、预校验结果、提交者、导入批次及生成台账引用；文件沿用既有安全存储和租户权限。TASK-016 再做高级字段映射、复杂历史迁移和导入工具化强化。

所有写命令包含幂等键；可变对象检查 expected_version。幂等作用域至少包含租户、操作者、动作和来源对象；相同键不同参数返回冲突，不重用其他来源的结果。重放前仍检查当前权限与数据可见性。

## 8. 必须验证的验收场景

以下数据库及并发语义必须在真实 PostgreSQL 验证，不能用 SQLite 或全 mock 替代：

1. 一份合同两张订单，防超合同额度；单张订单分两批收货，净剩余量准确。
2. 收货 5 件，4 件合格、1 件隔离；待检/隔离/客户所有均不进入可用量。
3. SN 重复、并发重复、同件重复入库失败；不同租户及符合身份策略的不同型号不误冲突。
4. 两个并发收货争抢订单剩余量，成功总量不超收，失败事务无残留。
5. 两个并发移库争抢同一 SN/批次，不能负库存或产生双位置；失败不丢成本。
6. 同键重放不增台账；同键不同内容冲突；不同来源同键互不串单；重放前撤权仍拒绝。
7. 质检部分拆分与内部移库数量/成本守恒，SN 成本及批次成本层来源不丢失。
8. 错误收货冲销恢复净收货量与成本；重复冲销拒绝；有后续移动时返回依赖阻断。
9. 已生效采购合同及已过账记录不能被编辑/删除；供应商主数据变更不修改历史快照。
10. 已知/暂估/未知成本明确区分，零成本与未知成本不同；对账差异可定位，不用零填补。
11. 期初导入预览不改库；错误整批回滚；相同文件换键/换行序不重复入账；期初截止边界有效。
12. 跨租户列表、详情、聚合、SN 搜索、文件下载、导入及任务均受限；无成本权限响应不泄露成本。
13. 空库迁移及 TASK-007 升级通过；原报价审批、发布修订、合同核心回归保持通过。

真实浏览器验收至少完整演示：建采购合同/订单 → 两批收货 → 部分合格/隔离 → SN 查询 → 移库 → 对账；另演示一次期初导入预校验失败再成功提交。

至少验证两个租户上下文切换，并用不同权限账号检查仓库与成本视图。保留桌面和移动窄视口截图，记录真实视口与导出尺寸差异。组件 HTTP mock 测试、真实浏览器测试和手工截图证据分别标记。
