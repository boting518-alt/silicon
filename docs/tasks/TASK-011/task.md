二、产品目标和边界

让经营人员可以回答：

- 哪个客户还欠多少钱，何时到期？
- 公司还应付哪个供应商多少钱？
- 哪些资金已经实际收到或付出，尚未分配到业务单据？
- 哪些款项属于预收、预付或质保金？
- 哪些合同已开票、已登记进项票，哪些尚未开票？
- 一笔资金如何对应多个应收/应付项目？
- 发生退货、金额调整或退款后，余额如何变化？

本轮实现经营资金子台账，不实现：
- 法定总账、会计凭证体系、财务报表或自动收入确认。
- 税务申报、税务平台开票、发票验真。
- 银行直连、支付网关、真实转账或自动扣款。
- 自动读取银行流水、OCR 或 AI 财务 Agent。
- 多币种换汇、汇兑损益、跨客户/供应商轧差。
- TASK-012 售后、维修、备件和 RMA。

“确认实收/实付”表示人工登记已发生的资金事实，
不得调用外部金融服务或宣称系统已完成转账。

本轮统一沿用 CNY；遇到其他币种明确拒绝，不隐式换算。

三、先固定领域模型与计算口径

在编码前检查现有模型，提交必要 ADR，明确：

1. 合同约定金额与付款节点。
2. 应收/应付项目及其到期日。
3. 实际收款/付款事实。
4. 核销分配关系。
5. 预收/预付余额及后续使用。
6. 退款事实与原资金来源。
7. 应收/应付调整及质保金释放。
8. 发票登记及其业务关联。

不能把以上对象合并成一个可直接编辑的“已付款金额”。

核心口径：
- 合同金额不是收入。
- 应收不是已经收到的资金。
- 开票不是收款，收货不是付款。
- 核销是已有资金与债权债务的分配，不再次产生现金流。
- 质保金是原合同价款的一部分，不能额外增加合同总额。
- 退货不自动代表退款已经发生。

金额使用 Decimal/NUMERIC 和十进制字符串，
不得用浮点数参与金额比较、汇总和持久化。
明确小数位、舍入方式及日期/到期日时区口径。

四、应收应付

1. 复用已有客户、供应商、销售/采购合同与订单身份。
   不另建重复的往来单位、合同或订单系统。

2. 支持从有效业务来源建立应收/应付计划，
   优先复用冻结合同中的付款节点。
   没有完整节点时允许有权限人员显式建立计划。

3. 每项至少包含：
   方向、往来单位、来源合同/订单、业务节点、
   应收/应付金额、到期日、说明及状态。

4. 区分计划草稿与已确认债权债务。
   默认显式确认，不因签约、发货或收货重复自动生成。

   若采用业务事件触发，必须记录唯一来源，
   并证明事件重放不会重复生成。

5. 支持分期、订金、尾款及质保金。
   同一合同计划不得因重复生成、修改节点或并发确认而超额。
   对变更合同金额的场景使用有来源的调整，
   不直接覆盖原确认金额。

6. 已确认项目不可直接删除或改写原金额。
   用追加调整、冲销或明确更正关系保留历史。

7. 展示：
   原金额、调整金额、有效金额、有效核销、
   剩余余额、到期情况和来源。

8. 逾期按未结余额及明确到期日计算。
   未到释放条件的质保金不得虚构到期日并计入逾期。

五、实收实付登记

1. 支持草稿、确认、受控冲销。
2. 每笔至少记录：
   收/付方向、往来单位、金额、实际发生时间、
   收付方式、内部账户标识、外部流水参考号、
   经办人和备注。

3. 内部账户仅是资金归属分类，
   不展示虚构银行余额或声称已连接银行。

4. 确认后保留不可变资金事实。
   重复提交不重复记账；并发确认只能生效一次。

5. 对人工重复录入建立明确防重规则：
   区分命令幂等与业务流水重复。
   外部流水号按已定义的账户/方向等作用域检查；
   缺少流水号时允许显式人工登记并保留审计，
   不假装能保证所有线下业务绝不重复。

6. 资金登记成功但响应丢失时，
   前端重试必须复用同一幂等意图。

六、部分与多对多核销

1. 一笔收款可分配到同一客户多个应收项目。
2. 一个应收项目可由多笔收款分次核销。
3. 应付与付款遵循对称规则。
4. 支持部分核销和剩余未分配金额。

5. 后端验证：
   - 同租户、同往来单位、同币种、方向匹配。
   - 资金事实和债权债务均有效。
   - 分配金额为正。
   - 不超过资金可分配余额。
   - 不超过项目未结余额。
   - 同一请求内不重复累计同一分配目标。

6. 多行核销必须原子提交。
   任一分配无效时整笔请求回滚，不留下部分成功。

7. 并发争用资金或未结余额不能超核销。
   沿用项目锁顺序，记录必要 ADR。

8. 撤销核销追加逆向关系，
   同时恢复资金可分配额和项目未结余额，
   不删除原分配，不产生第二次现金流。

七、预收预付、退款和质保金

预收/预付：
- 允许确认资金时尚未核销到应收/应付项目。
- 明确区分“预收/预付”与普通待分配款。
- 后续应用到项目只新增核销，不新增收付款。
- 不得把未分配余额自动显示为收入或利润。

退款：
- 客户退款关联原收款；供应商退款关联原付款。
- 本轮每条退款明细关联一个原资金来源；
  多来源退款可分行处理，不引入不清晰的总额池。
- 退款申请/草稿不影响实际资金余额；
  确认实际退款后才产生资金事实。
- 不得超过原资金在扣除有效核销、既有退款后
  的可退余额。
- 已核销资金需要先按明确顺序撤销相应核销，
  才能释放可退金额；退款不能暗中修改原核销。
- 并发或重复退款不得超退。
- 退款错误更正使用逆向记录，保留原事实与来源。

退货衔接：
- 引用 TASK-010 实收销售退货，可发起应收减少调整，
  但需要显式金额确认。
- 减少金额基于商业约定，不使用设备出库成本。
- 同一退货来源不能重复确认同一调整。
- 调整不得使有效应收小于当前有效核销；
  应先撤销必要核销，再调整，再登记实际退款。
- 退货不自动生成真实退款，不改写库存和设备历史。

质保金：
- 在原合同金额内拆分，不重复记应收/应付。
- 保存释放条件或日期、释放确认和后续到期日。
- 释放只是改变可到期/结算状态，不新增一笔债权债务。
- 支持释放后分次收付与核销。

八、发票登记

1. 支持销项/进项发票的人工登记。
2. 至少保存：
   发票标识、类型、开票日期、购销双方、
   币种、含税金额、可选不含税金额和税额、
   关联合同/订单及备注。

3. 没有已确认税费规则时，
   明确登记人工提供的金额与“税额未确认”等状态。
   不擅自默认税率或推定可抵扣。
   若登记金额三项齐全，校验勾稽关系。

4. 支持部分开票和同一业务来源多张发票。
   定义有效开票额度和红字调整后的净额规则，
   拒绝无来源的重复开票金额。

5. 对已确认发票使用追加作废/红字关联等业务记录，
   不物理删除或覆盖历史。
   这是内部登记，不代表税务平台操作成功。

6. 支持发票与多个本方业务来源的金额分配时，
   校验同租户、同往来单位、金额合计与重复引用。
   不强制发票与每笔资金一一对应。

7. 发票登记不自动创建实际资金、不自动核销，
   不改变合同金额和库存成本。

8. 如实现附件，复用现有受保护文件基础设施，
   包括租户、授权、下载和引用保留规则。
   如只提供档案编号，应如实标为登记引用，
   不伪装成已经上传或验真。

十一、对账与验证

建立可解释的对账检查，至少验证：

- 应收/应付有效金额 = 原确认金额 + 有效调整。
- 未结余额 = 有效金额 - 有效核销。
- 原资金金额 = 有效核销 + 有效退款 + 可用余额。
- 逆向后汇总与明细一致。
- 发票分配金额与有效登记金额一致。
- 已作废或冲销事实不重复进入有效汇总。

原资金守恒按各来源计算；
经营现金流另按实际收付及退款方向汇总，
不可再次扣减核销金额。

使用既有隔离真实数据库测试环境。
禁止对常驻业务数据库运行测试。

必须覆盖：
1. 同合同分期生成、防重复及额度约束。
2. 一款多项、一项多款、部分核销。
3. 跨租户、跨往来单位、方向不符和超核销。
4. 并发争用同一资金/项目，只允许合法总额生效。
5. 多行核销失败整体回滚。
6. 撤销核销恢复两端余额。
7. 预收预付应用不重复记现金流。
8. 已核销资金退款限制、部分退款、防重和并发。
9. 退货→解除核销→应收调整→实际退款的闭环。
10. 质保金释放不重复增加合同金额或债权债务。
11. 发票部分登记、防重、红字/作废及净额检查。
12. 查询/写入权限、撤权后的重放与摘要清除。
13. 无财务权限的原合同/设备/订单页面保持可用。
14. 既有数据迁移、对账和 TASK-010 核心回归。
