二、业务目标与边界

形成真实业务闭环：

按设备/SN 查询客户及交付记录
→ 建立售后工单
→ 分派、诊断和维修
→ 预留/领用备件
→ 记录拆件与装件
→ 维修后测试和客户确认
→ 关闭工单
→ 故障旧件返供应商维修或换货
→ 收回、检验和处置。

经营人员应能查明：
- 哪台设备出现什么故障，由谁处理？
- 设备目前由谁保管，处于哪个维修阶段？
- 当前装机配置与销售时配置有何变化？
- 哪个新件替换了哪个旧件？
- 备件来自哪次采购或入库？
- 旧件在客户处、隔离区、供应商处还是已处置？
- 工单发生多少材料、人工及其他费用？
- 哪些供应商返修件尚未收回？

本轮不实现：
- 自动远程控制客户设备、监控采集或硬件诊断 Agent。
- 自动向客户、供应商发送消息。
- 客户自助门户、物流平台和维修商平台集成。
- 复杂 SLA 计费引擎、续保产品、订阅收费。
- 自动税务开票、真实转账和会计总账。
- 任意无来源的历史设备建档或批量导入。
- TASK-013 及后续任务。

使用人工诊断、人工测试和明确操作确认，
不得把人工登记描述成自动硬件认证。

三、先确定设备、库存与维修模型

实施前通过 ADR 明确以下边界：

1. 稳定设备身份：
   设备 ID、整机 SN 和既有销售来源保持不变。

2. 配置历史：
   销售/装配时配置是不可变历史；
   维修后当前配置由有效安装关系投影。
   不改写原报价、合同、完工或发货快照。

3. 所有权与保管位置：
   客户设备送修不代表公司重新购入该设备。
   客户旧件、公司备件、供应商替换件必须区分。

4. 售后返修与销售退货：
   客户设备暂时送修，不自动恢复订单待履约数量，
   不自动冲销销售成本、应收或登记退款。

5. 维修费用与库存成本：
   材料消耗、人工成本、其他费用和对客收费分开。
   不把客户持有资产计入公司自有库存价值。

6. 供应商 RMA：
   发出返修表示保管地点变化，
   不直接视为采购退货、报废或退款。

禁止新增一套脱离现有库存台账的“备件库存”。

四、售后工单

1. 从同租户已有设备档案建立工单，
   关联客户、合同、订单、设备及必要交付来源。

2. 对已发货设备开展售后；
   尚未交付的生产返工继续归属原生产流程。
   明确拒绝误选无售后来源的设备。

3. 至少记录：
   工单编号、故障描述、报修时间、联系人、
   服务方式、优先级、负责人、计划处理时间、
   诊断、解决方案及历史事件。

4. 服务方式至少支持：
   - 远程指导：人工记录，不实际控制设备。
   - 上门维修：设备仍在客户处。
   - 返场维修：记录实际接收和归还。

5. 状态至少表达：
   待受理、处理中、等待备件/外部处理、
   待验证、已解决、已关闭、已取消。
   可调整具体命名，但需有明确转换规则和服务端约束。

6. 区分“问题已解决”和“工单已关闭”。
   关闭前检查：
   必要测试、处理结论、设备归还或保管状态、
   未退领料及未处理实物。

   供应商 RMA 可独立延续，但必须明确关联和负责人；
   不能关闭后隐藏仍在供应商处的旧件。

7. 取消仅适用于没有未处理实物/费用依赖的情况。
   已领料或已换件不能靠取消工单抹除事实。

8. 支持受控重开或追加后续工单，
   保留原关闭记录和重开原因，不覆盖历史。

五、保修判断

1. 复用已有保修信息和交付/验收事实。
2. 保存本次服务适用的保修依据、判断结果和经办人。
3. 没有明确保修条款时显示“待确认”，
   不默认一年、三年或免费维修。
4. 支持保内、保外和人工批准的特殊处理，
   原因与依据可追溯。
5. 保修判断不自动生成收费或资金事实。

本轮不查询外部品牌保修系统，
不将内部判断标为厂家官方认证。

六、返场接收与归还

1. 记录设备实际接收时间、外观、附件清单、
   经办人、客户身份及存放位置。

2. 接收客户设备时：
   保留原设备 ID，不新增重复整机；
   不增加公司自有成品库存价值；
   不改变销售订单净交付数量。

3. 归还必须关联原接收记录，
   防止未收到先归还、重复归还和跨设备归还。

4. 区分设备保管状态与维修状态。
   修好了但尚未归还，页面必须明确显示。

5. 重复提交和并发接收/归还只允许一次合法生效。

七、备件预留、领用和退回

1. 使用现有合格、自有且可用的库存，
   继承 SN/批次、成本层和来源规则。

2. 备件预留关联工单，考虑其他销售、装配和维修占用。
   不允许不同业务各自认为同一件库存可用。

3. 预留必须能释放；领用后不能再当作未领用预留释放。
4. 领用记录实际数量、位置、人员及工单用途。
5. 未使用备件可以退回：
   - 回原实物/批次和成本来源。
   - 明确是否需要重新检验。
   - 不超过本工单尚未使用且未退回数量。

6. 已安装备件不能直接走“未使用退料”路径。
   必须通过有历史关系的拆卸/换件处理。

7. 并发领用、重复退料和跨工单引用由后端防护。

八、设备换件与配置历史

1. 换件明确关联：
   工单、设备、原有效安装位置、旧件及新件来源。

2. 新件必须：
   - 来源有效。
   - 已按受控流程领用到本工单。
   - 未安装到其他设备。
   - 满足既有可验证的兼容要求。

   缺少自动兼容规则时，
   保存有权限人员的人工确认和依据，
   不伪装为系统已自动验证。

3. 确认换件在同一事务内完成：
   - 关闭原有效安装关系。
   - 追加新安装关系。
   - 处理领用件的实际消耗/安装去向。
   - 登记旧件的实际去向。
   - 追加审计与设备履历。

4. 同一设备同一安装位置不能并发安装两个有效部件。
   一个 SN 件不能同时有效安装在两台设备上。

5. 旧件去向至少区分：
   客户保留、公司代管隔离、供应商返修、待处置。
   所有权单独记录，不能仅凭去向推定转为公司资产。

6. 同 SN 的维修后重新安装应复用原实物身份；
   不同 SN 的供应商替换件建立明确替换关系，
   不修改旧件 SN 来冒充新件。

7. 支持无换件的维修结案。
8. 换件后要求重新记录适用于当前配置的测试结果；
   旧配置的通过结果不得自动沿用。

9. 错误换件登记通过受控逆向或更正处理。
   有后续安装、领用、RMA、归还等依赖时明确阻止，
   不删除历史或直接改当前安装行。

九、旧件与供应商 RMA

1. 从可追溯故障件建立 RMA，
   关联工单、设备、旧安装、采购来源和供应商。

2. 至少记录：
   内部编号、供应商受理编号、故障说明、
   送出日期、预计返回日期、负责人、
   处理结果、实际返回及后续去向。

3. 状态表达：
   草稿、待送出、已送出、供应商处理中、
   已返回待检、已完成或取消。

4. 送出必须对应实际可交接实物。
   同一 SN 不得同时出现在两个有效 RMA。
   供应商不匹配采购来源时，需要明确授权依据，
   不能静默把旧件归给任意供应商。

5. 至少支持两种返回：
   - 原件修复返回：保持原实物身份。
   - 换件返回：保存旧件与新件的替换关系。

6. 返回不自动合格；
   经检验和明确所有权/成本处理后才能成为可用备件，
   或归还客户、重新安装。

7. 部分返回按明细记录，剩余件仍为在外状态。
   不因一个明细返回就把整批全部关闭。

8. 报废或客户放弃所有权属于独立明确处置。
   不因为供应商不修就自动报废或转为公司资产。

9. 保管在外、待检、已安装和可用库存不能重复计数。
   库存/保管台账与 RMA 状态可以相互对账。

十、维修成本与对客收费

1. 材料成本取实际领用来源，
   消耗确认时计入工单材料成本，避免领用与安装重复累计。
   未使用退料与受控逆向按原成本恢复。

2. 人工至少记录：
   人员、工作时间或工时、计价依据、成本金额及说明。
   没有真实标准时明确人工登记，不默认市场费率。

3. 其他费用记录类型、金额、发生日期和依据。
4. 成本与对客服务报价/收费分开，
   保内成本不自动变成客户应收。

5. 对客收费需要明确服务收费依据及确认。
   与 TASK-011 集成时使用明确的新服务来源类型，
   不伪造原销售合同增额，不绕过来源额度校验。

6. 收款仍由 TASK-011 实收与核销流程完成；
   工单按钮不得直接把收费标记为“已收到”。

7. 若供应商维修产生费用，
   使用明确的供应商维修费用来源衔接应付。
   不自动增加原采购合同金额。

8. 成本、收费及资金摘要分别按权限读取；
   没有财务权限不影响基础售后操作，
   没有库存成本权限不泄漏材料成本。
