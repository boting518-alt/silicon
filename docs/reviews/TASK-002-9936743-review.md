## 实现核查

### OIDC、会话和请求保护

`identity/oidc.py` 锁定配置的 Keycloak issuer 与四个精确 discovery endpoint，不跟随任意发现地址；使用 S256 PKCE、固定 RS256、RSA JWKS key/kid、签名及 issuer/aud/azp/sub/iat/exp/nonce 校验。没有发现接受任意算法或错误 audience 的路径。

`identity/routes.py` 的 state 与独立随机浏览器 Cookie 都以 hash 查找；回调先 DELETE RETURNING 并提交消费登录尝试，再兑换授权码。异浏览器不能取得尝试，已消费回调不能重放，失败不会重新开放 state。真实 IdP 回调/重放测试与 JWT 替身的负向声明测试已分开评价。

登录静态路径会删除当前旧 session 后创建新随机 session；数据库只存 token/CSRF hash，会话上限同时受本地期限和 ID token exp 限制。禁用用户在每次 authenticated 查询拒绝，租户事务另查 active membership。退出原子删除本地会话并审计，随后返回 IdP 前通道退出地址；IdP 不可用不会恢复已删除的本地会话。

Cookie 设置为 __Host、Secure、Path=/，会话 HttpOnly、SameSite=Lax；写请求使用服务端 CSRF hash 和固定 Origin。前端只读取独立 CSRF Cookie、调用同源 API，没有凭请求体指定 actor 的认证入口。新 OIDC 用户没有自动 membership。没有发现生产登录后门；production 启动拒绝保留。

会话轮换的旧 token 删除分支主要依据代码检查；真实集成实际覆盖登录、退出后旧 Cookie 拒绝和再次登录，不将这些自动扩大为所有多窗口/并发登录行为已验证。
