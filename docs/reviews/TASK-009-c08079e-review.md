## R1 / P2：冲销完工后无法沿用原设备 SN 重新完工

定位：apps/api/src/silicon/assembly/service.py 的 complete、reverse；apps/api/migrations/versions/0010_assembly.py 的 asm_devices 实物唯一约束。

复现流程：

1. 工单领料齐套，以 FIN-001 完工，生成实物、成品成本层、设备与安装记录。
2. 在成品无后续依赖时，执行错误完工逆向。当前实现恢复在制、关闭原安装关系，工单回到 in_progress；原实物和设备历史按要求保留。
3. 使用最新 expected_version、新幂等键及原 SN FIN-001 再次完工，例如更正第一次录错的成品库位。
4. complete 对 inv_units 中任意同 SKU/SN 历史记录直接返回 SERIAL_ALREADY_EXISTS，没有区分已逆向且无有效库存的原设备。
5. 即使仅移除这条查询，asm_devices 的 UNIQUE(tenant_id,inventory_unit_id) 仍会阻止当前“每次 INSERT 新设备记录”的实现复用原实物。

影响：用户可以撤销错误完工，却不能以同一物理设备身份完成更正；被迫换一个虚构 SN 或依赖人工改库。错误完工逆向恢复了数量和成本，但没有提供可用的后续完成路径。此问题针对已授权的错误更正，不要求新增正常返工、售后拆解或换件。

独立验证：执行真实 complete 函数，数据库边界提供“逆向后 in_progress、需求已齐套、在制成本完整、普通目标库位、原 SN 历史实物仍在”的状态，得到 SERIAL_ALREADY_EXISTS。源码同时确认 reverse 保留原实物/设备、迁移的第二层唯一约束。探针使用持久化替身，不冒称真实 PG/API 全流程复现。
