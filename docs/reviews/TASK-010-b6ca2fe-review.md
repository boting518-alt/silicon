## R1 关闭依据

原问题是设备及装配页面强制调用要求 `delivery.read` 的设备聚合接口，导致仅保留原 `device.read` 的用户失去基础设备查询和装配初始加载。

修复集中在 `apps/web/src/Assembly.tsx`：

1. 基础列表、后端搜索和详情恢复使用 `/assembly/devices`。详情重新请求后端校验权限，不直接把列表缓存当作最新详情。
2. 装配初始加载不再依赖交付接口；设备读取按 `device.read` 判断。
3. 交付历史由独立状态保存，打开基础详情后才按 `delivery.read` 增强加载。
4. 交付请求返回 403 时，清除历史并明确提示权限不足，基础详情继续可用；其他错误不伪装成功。
5. 刷新、搜索、重开或关闭详情会清除旧交付信息；请求代次和企业上下文检查阻止迟到响应在关闭详情或切换企业后重新显示。
6. 基础设备列表不再根据缺失交付信息猜测“待测试/未发货”。

ADR-015 明确了 `device.read` 与 `delivery.read` 的独立投影范围，以及成本仍需 `inventory.cost`、关联 ID 不授予关联对象访问权的规则。本轮未修改后端生产权限、默认角色或迁移来扩大授权。
